# Спикеры из Контур.Толк

Приложение и `notetaker ktalk sync` берут имена участников и время их слов из готовой
транскрипции записи Толка. Нужна запись со статусом `complete` и завершённой
транскрипцией. Локальное распознавание текста не заменяется.

## Настройка в приложении

1. Откройте «Настройки → Толк», укажите HTTPS-адрес пространства без пути.
2. Создайте персональный ключ по [официальной инструкции](https://support.kontur.ru/talk/86797-personalnyj_apiklyuch_dostupa_v_tolke), введите его и нажмите «Сохранить».
3. Нажмите «Проверить»: появится имя владельца ключа. Сохранённый ключ не показывается; его можно заменить.

AI настраивать не требуется. Ключ хранится в Windows Credential Manager или
macOS Keychain. Автоматическое именование включено по умолчанию после сохранения
ключа. Оно работает и для Local: интеграция только читает данные Толка.

Автоматическая сверка доступна только новым встречам, записанным этой установкой
приложения. После завершения записи её UUID попадает в реестр в локальном каталоге
данных пользователя, вне общей библиотеки. Встречи коллег, импорты и записи до
этой версии автоматически не подхватываются; наличие микрофона или названия не
считается доказательством происхождения. При переносе библиотеки на другой путь
меняется ключ локального состояния: реестр теряется и прежние встречи больше
не подхватываются автоматически.

После финального распознавания выполняется первая попытка. Без ошибок следующие
точки приходятся примерно на 3, 10 и 30 минут. Только успешный ответ Толка
расходует точку: ошибка сети или ключа сохраняет текущую точку и вызывает повторы
через 1, 5, 15, затем каждые 30 минут, в пределах суток. Отсутствие записи после
четырёх ответов заканчивает попытки тихо. Неоднозначность и отказ проверки времени
или текста останавливают автоматическую сверку с причиной для ручного действия.
Занятый lock встречи повторяется через 15 секунд.

На вкладке транскрипта откройте «… → Имена из Толка». Просмотрите
время записи, смещение, сходство текста и назначения. Неоднозначную запись можно
выбрать явно. «Применить» сохраняет имена; toast «Отменить» возвращает прежний
транскрипт, если он после этого не менялся. Рядом со спикерами указан источник;
tooltip содержит время записи, сохранённое приложением.

При включённой библиотеке голосов автоматически запоминаются только
зарегистрированные участники Толка. Запись голоса привязана к устойчивому
`ktalk-…` ID, а не к имени. Имена голосовых записей уникальны без учёта регистра
и пробелов по краям: при совпадении с другой identity имя применяется к транскрипту,
но голос не сохраняется; уточните имя, если это другой человек. Гости
автоматически не записываются в библиотеку голосов. Их можно явно назвать
в меню спикера; приложение использует сохранённые проверенные интервалы этой
записи для ручного enrollment. Связанный с тем же голосом спикер может добавлять
образцы; совпадение имени без этой связи не объединяет голоса.

Для каждого участника берутся интервалы его слов без слов других участников
(включая гостей) с запасом 300 мс. Интервалы переводятся в локальное время
проверенным смещением и обрезаются по аудио. Нужны не менее 6 секунд чистой речи,
фрагменты от 1,5 до 15 секунд, не более восьми. При недостатке речи или удалённом
аудио голос пропускается с пояснением. Собственный голос обучается с микрофонной
дорожки только для встречи в локальном реестре и через собственную voice identity,
без отдельной записи `ktalk-*`. Остальные зарегистрированные участники обучаются
с системной дорожки. Профиль Толка не содержит ID: владелец определяется только
по единственному совпадению имени среди зарегистрированных участников. Если
совпадение неоднозначно или отсутствует, автоматическое обучение пропускается.
Для чужой встречи или импорта ручная сверка не
меняет `me` на владельца ключа и не обучает на нём собственный голос.

Если библиотека голосов выключена, после первого успешного sync один раз для
этой библиотеки предлагается её включить. Для разных написаний имени доступны
ручные объединения людей; автоматического объединения латиницы и кириллицы нет.

После применения имён запрос обучения сначала сохраняется как pending в локальном
состоянии. При выходе операции отменяются, приложение ждёт их завершения. После
перезапуска pending enrolment получает транскрипцию Толка заново и повторно
проверяет сопоставление. Pending хранит UUID встречи, ID записи Толка и точную
revision транскрипта после сверки и время, раньше которого обучение не начинается.
Отмена очищает запрос; правка транскрипта или исчезновение соответствующего
источника Толка прекращает обучение. У pending нет срока давности: окно 24 часа
относится только к автоматическому поиску записи, а не к обучению после сверки. Удалённое аудио и недостаточная чистая речь завершают обучение
явным пропуском. Текст Толка не сохраняется; для ручного именования гостей
локально остаются только интервалы времени.

Обучение начинается не раньше чем через две минуты после сверки и только после
исчезновения уведомления; до этого «Отменить» возвращает транскрипт, а отпечатки
и кэш этой сверки ещё не записаны. После начала обучения отмены нет: неверное
имя исправьте в меню спикера, а неверный голос удалите в настройках «Голоса».
В текущем сеансе две минуты измеряются монотонными часами. После перезапуска
уведомления и отмены нет; обучение ждёт и две минуты нового сеанса, и сохранённый
срок по часам компьютера. Ручная правка спикера завершает отмену сверки; коллизия
имени не записывает ни голос, ни embedding в кэш.

Все writers `config.toml` используют общий эксклюзивный lock рядом с файлом.
Настройки AI заменяют только свои таблицы и сохраняют `[ktalk]`, включая
неизвестные поля; настройки Толка заменяют только `[ktalk]`. Синтаксически
повреждённый TOML не перезаписывается: ошибка называет файл.

## CLI

В `config.toml` достаточно одного раздела:


```toml
[ktalk]
base_url = "https://<space>.ktalk.ru"
credential_id = "work"
api_key_env = "NOTETAKER_KTALK_KEY"
```

Файл находится в каталоге конфигурации notetaker: на Linux обычно
`~/.config/notetaker/config.toml`, на Windows `%APPDATA%\notetaker\config\config.toml`. Разделы AI (`[defaults]`, `[[providers]]`) для Толка не нужны.
Ключ в TOML не записывайте. Укажите его в переменной `NOTETAKER_KTALK_KEY`
средствами своего окружения, не публикуя значение в shell history.

Для OS credential store удалите `api_key_env`. Ключ сохраняется через
`ktalk::Settings::save_key` в существующий `CredentialStore`: Windows Credential
Manager или macOS Keychain. CLI не имеет команды ввода ключа: сохраните его в приложении
или используйте переменную окружения. На Linux OS-хранилище пока не поддержано.
Credential привязан к origin пространства: после смены адреса сохраните ключ
заново. Настройки содержат только адрес и идентификатор ключа.

```sh
notetaker ktalk status
notetaker ktalk sync /path/to/meeting --dry-run
notetaker ktalk sync /path/to/meeting
notetaker ktalk sync /path/to/meeting --recording <id> --dry-run
```

`status` проверяет профиль и выводит имя владельца ключа. Dry run показывает
запись, время, смещение, score проверки текста и таблицу назначений; ничего
не сохраняет. `--recording` выбирает запись явно в пределах просмотренного
периода. Явный выбор тоже требует пересечения хотя бы на половину короткого
интервала и надёжного сопоставления времени и текста.

## Сопоставление и ограничения

Записи просматриваются страницами по 100. Просмотр завершается только если
все записи страницы старше начала встречи минус сутки, страница короче 100
или не приносит новых ID. Последняя старая запись на несортированной странице
не завершает просмотр. Повторные ID учитываются один раз. После 30 полных
страниц без условия остановки возвращается ошибка, выбор по неполным данным
не производится.
Выбирается максимальное пересечение интервалов, не меньше половины короткого
интервала. Разница до 10% между лучшими кандидатами считается неоднозначностью.

Активность локальных реплик сравнивается с объединением интервалов слов Толка.
Смещение ищется с шагом 100 мс в пределах 180 секунд в обе стороны от разницы
времени старта. Поиск ограничен 131072 отсчётами по 100 мс, включая запас
по 180 секунд с каждой стороны. Более длинный интервал вызывает ошибку;
автоматического понижения точности нет. Стоимость поиска ограничена 3601 × 2048
операциями над 64-битными словами с двумя shift/popcount на слово.
Лучший score активности должен превосходить лучший score вне окрестности
±2 секунды хотя бы на 10% от лучшего score. Иначе смещение неоднозначно,
даже если текст похож: повторяющаяся речь и длинные непрерывные монологи
могут не дать надёжного временного ориентира.

Проверяются только реплики целиком внутри выровненного интервала записи Толка.
Реплики вне него остаются без изменений, в том числе при частичной записи.
До 64 равномерно выбранных реплик, включая первую и последнюю, проверяются по
token Dice без учёта регистра и пунктуации. Учитываются только буквенные слова
от трёх символов, кроме небольшого списка служебных слов и заполнителей RU/EN.
Средний score должен быть не меньше 0,5. Нужны 30 разных совпавших содержательных
слов и минимум шесть подтверждающих реплик. Подтверждающая реплика имеет Dice
от 0,6 и хотя бы три совпавших слова. Среди выбранных реплик с минимум
четырьмя содержательными словами подтверждающих должно быть не меньше 60%.
Порог подобран на реальной встрече: два распознавателя на одном и том же звуке
совпадают в реплике на 0,44-1,0 содержательных слов (медиана 0,83), короткие
реплики дают меньше. При пороге 0,8 подтверждалась только половина реплик.
Если реплик или содержательных слов недостаточно даже для проверки,
возвращается «запись слишком короткая для надёжной сверки».
Подтверждающие реплики должны охватывать хотя бы треть пересекающегося интервала; если
он короче трёх минут, весь интервал с допуском 200 мс на границы сетки.
Одинаковое приветствие только в начале встречи не является подтверждением.
Синтетические тесты проверяют
смещения +37 и -95 секунд с jitter слов, молчащим участником и чужим текстом.
Порог проверен на одной реальной встрече; широкая калибровка не проводилась.
При неуспехе ничего не применяется: «не удалось надёжно сопоставить время».

Реплика получает участника с долей не меньше 60% пересекающейся речи.
Слова внутри длинного chunk учитываются по отдельности. Равное разделение
между двумя участниками оставляет прежнего спикера. `me` получает имя владельца
ключа только для локально зарегистрированной записи и без подтверждённого имени. Подтверждённые имена и все реплики
с `edited=true` сохраняются. Это консервативно защищает также правки текста:
отдельного признака ручного изменения спикера в старом формате нет.

В `transcript.json` добавляется необязательный `ktalk_sources`: speaker ID ->
recording ID. Участники получают устойчивые `ktalk-<SHA-256 identity>` ID;
пользователи и гости имеют разные пространства ID. Повторный sync с теми же
данными не меняет revision. Старые файлы читаются без перезаписи. Старые версии
приложения читают новое поле, но могут потерять его при сохранении.
Сохранение использует revision check и блокировку встречи. Отмена допускается
только без локальных несохранённых правок и при точном совпадении revision;
поздние изменения другого writer не перезаписываются. Поиск обновляется,
конспект становится устаревшим. CLI-команда голосовые отпечатки не обучает;
приложение обучает их отдельно при включённой библиотеке голосов.
Metadata спикеров без оставшихся
реплик удаляется из встречи. Если имя `me` отличается от неподтверждённой
подсказки, её voice link удаляется вместе с подсказкой. Новые спикеры Толка
не наследуют voice links кластеров. Подтверждённые имена и их связи сохраняются.

## Приватность и сеть

Используются только GET к настроенному HTTPS host Толка: профиль, список записей,
транскрипция выбранной записи и медиа при обучении по прошлым записям. Ничего из библиотеки notetaker не загружается
в Толк. Query списка пустой; текст локальной встречи никогда не отправляется.
Текст транскрипции Толка существует только в памяти и не сохраняется на диск.
Сверка сохраняет только назначения спикеров, имена и ID записи-источника.
Обучение дополнительно сохраняет локальные отпечатки и журнал, описанные ниже.
Имена в локальном транскрипте затем могут попасть в Hybrid LLM обычным путём.

Редиректы запрещены. Таймаут соединения 10 секунд, чтения 30 секунд,
JSON-ответ ограничен 16 МиБ, медиа при обучении 300 МБ. Ключ и query не включаются в ошибки. Лимит Толка:
50 запросов в минуту на пользователя. Внутри одного процесса notetaker все
GET Толка, включая profile и transcript, разнесены минимум на 1501 мс общей
блокировкой: максимум 40 запросов за скользящую минуту. Другие процессы и клиенты
могут расходовать тот же лимит пользователя отдельно.
HTTP 429 вызывает понятную ошибку без
автоматического повтора. HTTP 401 означает, что ключ не принят.

Время начала и конца каждого слова и chunk проверяется до сопоставления:
`0 <= start <= end <= 86400000` мс. Значения за пределами суток, отрицательные
и перевёрнутые интервалы считаются некорректным ответом. Вычисления смещения
проверяют переполнение и возвращают ту же ошибку вместо паники.

Неизвестные поля `[ktalk]` сохраняются как TOML-значения и проходят round-trip
через настройки приложения. Интеграция их не интерпретирует. CLI читает общий
`config.toml`, но не имеет команды его перезаписи.

## Обучение по прошлым записям (0.33.0)

В настройках Толка выберите период: 30, 60 или 180 дней, по умолчанию 60.
Приложение посчитает записи с готовой транскрипцией и покажет примерный размер
загрузки, округлённый до десятков МБ, и число уже изученных записей.
Кнопка «Выучить голоса» запускает обработку после получения списка.
После завершения показан результат; «Повторить» доступно, если были пропуски.
Лимит списка: 30 страниц по 100; неполный список отклоняется.

Нужны включённая библиотека голосов и скачанные модели голосов. Если библиотека
выключена, сначала показано то же согласие, что после сверки. Обработка идёт
по одной записи, её можно остановить. Во время записи или финализации ASR
обработка приостанавливается без потери позиции. Очередь IDs и счётчики лежат
в private local state вне библиотеки и продолжаются после перезапуска.
Смена пространства требует нового плана; чужой host не получает старый запрос.

Используются профиль владельца, транскрипция, самое низкое готовое разрешение
и прежние чистые интервалы word timings. Гости не обучаются автоматически.
Историческая запись никогда не обучает собственный голос и не содержит
микрофонной дорожки notetaker. Участники с именем профиля пропускаются целиком:
профиль не даёт ID, по имени нельзя отличить владельца от тёзки. Отсутствие
владельца не мешает обучению остальных зарегистрированных участников. Их слова,
как и слова пропущенного тёзки, участвуют в исключении пересечений речи.
Собственный голос обучается только с микрофона встречи, записанной этой установкой,
или через явное «Это я». Уникальные имена и запрет enrolment по совпадению имени
сохраняются. Конфликт разрешается явным объединением людей.

Медиа загружается GET только с origin настроенного HTTPS-пространства,
без редиректов. Cap 300000000 байт, deadline тела 10 минут; API pacing сохранён.
MP4/AAC декодируется существующим native import path Symphonia в mono WAV
16 kHz, без внешнего ffmpeg и запасного decoder. Неподдержанный файл даёт ошибку.
MP4 и PCM находятся только во временном каталоге операции; он удаляется после
успеха, ошибки и отмены. Все такие каталоги лежат в одном
`<data-local>/tolk-learning-temp/`, вне библиотек. При запуске остатки после
принудительного выхода удаляются; файловая блокировка защищает активную операцию.
Перед скачиванием нужны место под оценку загрузки, декодированный PCM и запас
500 МиБ. Нехватка места останавливает очередь без потери текущей записи.
Для `embed` сначала потоково вырезаются только выбранные фрагменты в отдельный
WAV: не более восьми по 15 секунд, до 120 секунд PCM на человека. Воркер не читает
в память WAV всей встречи. Транскрипция остаётся в памяти. Ничего не загружается
из библиотеки в Толк.

Ключ запись/identity, привязанный к origin, сохраняется атомарно с отпечатком.
Повторная обработка его не добавляет. На человека остаётся до восьми образцов,
не более одного на известную запись. Новые записи вытесняют сначала образцы
без известного источника, затем самые старые; повторное доказательство одной
записи заменяет её образец. Разнообразие записей важнее количества фрагментов.

В завершении показаны люди, записи и причины пропусков. Сохраняются только
отпечатки и необходимые локальные metadata: имена, источники образцов,
keys идемпотентности, очередь и счётчики. Аудио в библиотеку не сохраняется.
