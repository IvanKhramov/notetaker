# Люди, серии и дайджест (0.9.0)

## Люди

«Люди» собирает участников календаря, подтверждённые имена спикеров,
связанные voice ID, имена из библиотеки голосов, ответственных за задачи
и ваши имя/алиасы из настроек. Email без учёта регистра - основной ключ.
Имена сопоставляются целиком: регистр, Ё/Е, начальный `@` и лишние пробелы
не учитываются. Разные email с одинаковым именем остаются разными людьми;
неоднозначное имя без email остаётся отдельной записью.
«Саша» и «Александр» объединяются только вручную.

Нажмите имя спикера или участника календаря, чтобы открыть карточку.
Меню `…` рядом со спикером сохраняет команды именования и исправления.
Карточка показывает email, алиасы, встречи от новых к старым с выдержками
конспекта, последние темы, открытые задачи, явные поручения и время речи.
Статистика использует те же интервалы и правила пересечений, что транскрипт.
Суммарное время измеряет речь, а не присутствие на встрече.

«Изменить человека» позволяет переименовать, скрыть или объединить выбранных
людей. Исходные имена сохраняются как алиасы. Скрытие убирает человека из
обычного списка; «Показать скрытых» позволяет вернуть его. Эти команды меняют
реестр, но не переписывают старые транскрипты и календарные данные.

SQLite хранит пересобираемые наблюдения. Явные объединения, имена, алиасы и
скрытие хранятся в `<library>/.notetaker/people.json`. Удаление индекса
их не теряет. Реестр людей можно синхронизировать; индекс и биометрия остаются локальными
в общей библиотеке. См. [общая библиотека](sharing.md).
Если исходные встречи удалены, их люди перестают показываться до появления
новых источников; пользовательские правки остаются.

Поручивший определяется только из явного поля в конце задачи:

```markdown
- [ ] Проверить релиз - Анна - завтра | Попросил: Иван
- [ ] Обновить документ - Иван - 30.10.2026 | Поручил: Анна
```

Также распознаются `requester:` и `assigned by:`. Авторство из свободного
текста не угадывается. На карточке поручившего видны и завершённые поручения.

«Сводка по человеку» берёт конспекты последних N встреч (1-100), без полного
транскрипта. Используется провайдер сценария «Конспект» и существующий
map-reduce. Если среди источников есть Local, разрешён только локальный
провайдер. Если модель недоступна, остаются конспекты и причина отказа.

## Серии

Повторяющиеся календарные встречи связываются по UID, который сохраняется
при разворачивании RRULE. Название и участники могут изменяться.
Без календаря используется точное нормализованное название и одинаковое
непустое множество подтверждённых имён спикеров. Это эвристика: имена
неназванных спикеров и похожие названия не угадываются.

В заголовке серии доступны предыдущая/следующая встречи и переход к списку
всех дат с количеством открытых задач. «С прошлой встречи» показывает решения
из разделов «Решения», «Договорились», `Decisions` и строки «Решили:»,
а также ещё открытые задачи именно предыдущей встречи.

Контекст попадает в начало `notes.md` только по кнопке «Вставить в заметки».
Перед вставкой задачи перечитываются; завершённые задачи не переносятся.
Вставка Local-контекста сначала делает целевую встречу Local. Дождитесь
сохранения собственных правок перед вставкой. Вставка доступна после окончания
записи и фоновой обработки. Переходы между встречами сами
ничего не добавляют в заметки.

## Дайджест

Выберите текущую или прошлую ISO-неделю либо произвольные локальные даты
в формате `YYYY-MM-DD`. Начало включительно, конец исключительно. Можно
ограничить выбор человеком и/или серией; расположение встреч внутри
поддерживаемой структуры библиотеки не меняет фильтры.

Дайджест содержит встречи, явно записанные решения, новые задачи,
просроченные открытые задачи и раздел по людям. Сроки сравниваются с текущей
датой или концом прошлого периода. Завершение задачи в более позднем конспекте
не закрывает автоматически похожую задачу в старом: измените исходный флажок.

LLM получает только конспекты Hybrid-встреч через провайдер «Конспект»,
с map-reduce для длинных периодов. Local-встречи остаются в обычных списках
с пометкой; их текст и задачи не передаются провайдеру дайджеста.
Без настроенной модели дайджест всё равно сохраняется со списками.

Недельный файл: `<library>/.digests/YYYY-Www.md`, где год относится к ISO-неделе,
например `2020-W53.md`. Произвольный период: `YYYY-MM-DD_YYYY-MM-DD.md`.
Повторная генерация того же периода атомарно перезаписывает файл, включая
генерацию с другим фильтром. Кнопки «Копировать» и «Показать в папке» доступны
после сохранения.

Настройка «Напоминать о дайджесте в пятницу в 17:00» изначально выключена.
Когда приложение открыто в пятницу после 17:00 по локальному времени,
появляется один toast за этот день работы приложения. Фоновый системный
планировщик и автоматическая генерация не используются.

## CLI и MCP

```sh
notetaker people --library /path/to/library
notetaker person anna@example.org --library /path/to/library
notetaker person 'Анна' --library /path/to/library
notetaker digest --week --prev --library /path/to/library
```

`person` печатает JSON карточки; неоднозначное имя требует email.
`digest` создаёт файл и печатает Markdown и путь.

Read-only MCP:

- `list_people()` - видимые люди из разрешённых встреч и задач.
- `get_person(person)` - имя, email или id; карточка без полного транскрипта.
- `get_series(meeting)` - UUID или путь встречи внутри библиотеки.
- `get_digest(start?, end?, prev?, person?, series?)` - данные периода без LLM
  и без записи файла; по умолчанию текущая неделя.

Все инструменты соблюдают `mcp_exclude_local` по исходной metadata.
При исключении Local библиотека голосов и личные алиасы настроек не служат
источниками людей. Сохранённые `.digests` не читаются через MCP: ответ строится
заново из разрешённых источников, чтобы ранее сохранённый Local-текст не утёк.
