# Установка в Windows

Скачайте `notetaker-v<версия>-windows-x64-setup.exe` со страницы
[Releases](https://github.com/IvanKhramov/notetaker/releases) и запустите его.
Сборки пока не подписаны: в SmartScreen нажмите **Подробнее → Выполнить в любом случае**.
Далее нажимайте **Далее**, при необходимости отметьте **Запускать notetaker при входе
в Windows** и создание значка на рабочем столе.

Установка выполняется только для текущего пользователя без запроса администратора,
по умолчанию в `%LOCALAPPDATA%\Programs\notetaker`. Ярлык появится в меню Пуск.
Удаление: **Параметры → Приложения → notetaker → Удалить**. Библиотека встреч и
пользовательские настройки сохраняются. Автозапуск можно включить или выключить
и в настройках приложения; значение `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\notetaker`
удаляется при деинсталляции.

Если установка не нужна, распакуйте дополнительный ZIP целиком и запустите
`notetaker-app.exe`. `notetaker.exe`, `notetaker-asr.exe` и DLL должны оставаться
рядом. Для каждого setup.exe и ZIP в релизе есть файл `.sha256`.

После принятия пакета в каталог WinGet станет доступна команда:

```powershell
winget install IvanKhramov.Notetaker
```

## Обновления

Приложение проверяет последний стабильный GitHub Release при запуске и затем раз
в 24 часа. Отключение: «Проверять обновления» и «Сохранить». Ошибки сети и ограничения
GitHub API не прерывают работу. «Позже» скрывает предложение до следующей проверки;
«Что нового» открывает страницу релиза.

«Обновить» доступно после завершения записи/чистового прохода и текущих загрузок.
Приложение скачивает setup.exe, проверяет SHA256, сохраняет изменения и завершается.
Временная копия CLI дожидается выхода GUI, запускает Inno Setup с
`/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /CLOSEAPPLICATIONS=no` и затем открывает GUI.
Используется текущий каталог установки. Для WinGet применяется тот же установщик
с тем же AppId. При ошибке установщика можно повторить установку вручную.
ZIP-копия после такого обновления тоже регистрируется как установленное приложение.

Перед установкой и удалением вызывается `notetaker-app.exe --quit` через IPC.
Он ждёт штатного завершения с сохранением данных; во время записи/чистового прохода
приложение отказывает и показывает сообщение. Завершите запись и повторите попытку.
Принудительное завершение процессов и Restart Manager не используются.

При первом переходе с 0.7.0 закройте все старые копии через «Выход» в трее:
эта версия ещё не поддерживает IPC `--quit`. Для последующих версий штатное
завершение выполняется установщиком.

## Диагностика

«Открыть папку логов»: `%LOCALAPPDATA%\notetaker\logs`.
Хранятся до пяти файлов примерно по 2 МБ. Произвольный stderr worker и текст panic
заменяются категориями, чтобы не сохранять случайно попавшие туда ключи или тексты
встреч. Для panic сохраняются место и backtrace; следующий запуск показывает диалог.
«Собрать отчёт» создаёт ZIP на рабочем столе (или в домашнем каталоге, если рабочий
стол не определён системой) и показывает файл в Explorer.
Отчёт содержит логи, версию/ОС/архитектуру и разрешённые общие параметры.
LLM-конфигурация, URL календарей, словарь, пути и содержимое встреч исключены.

## Первая публикация WinGet (для сопровождающего)

1. Опубликуйте draft релиза вручную. Workflow `Release` собирает setup.exe, ZIP и
   SHA256 по тегу `v*`; публикация запускает генерацию `notetaker-<версия>-winget.zip`.
   Альтернатива: `workflow_dispatch` с версией уже опубликованного релиза.
2. Установите `wingetcreate` и создайте начальный пакет локально:

   ```powershell
   winget install Microsoft.WingetCreate
   wingetcreate new https://github.com/IvanKhramov/notetaker/releases/download/v<VERSION>/notetaker-v<VERSION>-windows-x64-setup.exe
   ```

   Не соглашайтесь на автоматический submit. Укажите `IvanKhramov.Notetaker`,
   издателя Ivan Khramov, лицензию `MIT OR Apache-2.0`. Сверьте результат с шаблонами
   `packaging/winget`: InstallerType inno, Scope user, x64, локали ru-RU и en-US.
3. Получите готовый комплект из релиза либо выполните:

   ```powershell
   ./scripts/winget-manifests.ps1 -Version <VERSION>
   # Для уже скачанного установщика:
   ./scripts/winget-manifests.ps1 -Version <VERSION> -SetupExe ./notetaker-v<VERSION>-windows-x64-setup.exe
   winget validate --manifest ./target/winget/<VERSION>
   winget install --manifest ./target/winget/<VERSION>
   ```

4. На чистой Windows проверьте установку без администратора, ярлык, автозапуск,
   запуск ASR, два запуска GUI (одна иконка трея), обновление и удаление.
   Проверьте отказ установки/удаления во время записи и чистового прохода.
   Для локального manifest может понадобиться
   `winget settings --enable LocalManifestFiles` в elevated terminal.
5. Самостоятельно отправьте первый PR в `microsoft/winget-pkgs`
   (`manifests/i/IvanKhramov/Notetaker/<VERSION>/`) и дождитесь принятия.
6. Только после принятия при необходимости добавьте repository secret
   `WINGET_TOKEN` с правами, требуемыми `wingetcreate` для PR в winget-pkgs.
   Без секрета CI только прикладывает манифесты. С секретом последующие публикации
   вызывают `wingetcreate update ... --submit`. Релиз из draft публикуется вручную.

## Сборка и зависимости

Установщик: Inno Setup 6, `packaging/windows/notetaker.iss`. Скрипт
`package-installer.ps1 -Version <VERSION> -PayloadDir <каталог>` использует
проверенный staging из `package-windows.ps1`, устанавливает Inno Setup через
Chocolatey при необходимости, собирает setup.exe и SHA256. CI также сохраняет
установщик как artifact. Версия тега должна совпадать с версией workspace.

`winres` - только Windows build dependency для ресурса ICO в GUI exe.
Иконки хранятся в репозитории; `python scripts/generate-icons.py` воспроизводит
PNG 16/24/32/48/64/256, ICO и вариант записи без внешних Python-пакетов.
`reqwest` переиспользует версию и Schannel/TLS конфигурацию workspace, отдельный
клиент нужен, поскольку LLM-клиент не является публичным транспортом общего назначения.
`semver` и `sha2` уже есть в графе зависимостей; нужны для сравнения версий и проверки
установщика. `zip` уже используется ASR; у runtime включён только deflate для отчётов.
Crate `notetaker-runtime` отделяет эти функции от UI и ML; фича `distribution`
не нужна клиенту ASR для сбора stderr и раскрытия путей.
