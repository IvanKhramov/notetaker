# Распознавание речи (0.10.0)

ASR работает локально в отдельном процессе `notetaker-asr`. Модели не входят
в установщик. Язык и модель выбираются на встречу, ускорение и число потоков
задаются в настройках ASR.

## Модели и Авто

- **GigaAM v3**: русский, RNNT с пунктуацией, архив 170,2 МБ.
- **Parakeet TDT v3 int8**: 25 европейских языков, включая английский и русский,
  архив 487,2 МБ. В одиночном режиме язык сегмента остаётся неизвестным.
- **Авто (рус/англ)**: Silero VAD разбивает речь на чанки до примерно 29 секунд,
  Whisper tiny определяет язык каждого чанка. Русский декодируется GigaAM,
  остальные языки направляются в Parakeet. В `lang` сохраняется фактический
  код языка, например `ru` или `en`.

При первом запуске без `app.toml` Авто выбирается, если обе ASR-модели уже
установлены. Если tiny отсутствует, строка Авто в «Быстром старте» предлагает
докачать его. Сохранённый выбор существующих пользователей не меняется.
Одиночный режим требует только выбранную модель и Silero; Авто требует обе
ASR-модели, Silero и tiny:

```sh
notetaker-asr download auto
notetaker-asr check-model auto
```

Whisper tiny multilingual поддерживается Rust API sherpa-onnx 2.0.0 через
`SpokenLanguageIdentification`. Архив `sherpa-onnx-whisper-tiny.tar.bz2` занимает
116 204 861 байт, сохраняются только `tiny-encoder.int8.onnx` (12 937 772 байта)
и `tiny-decoder.int8.onnx` (89 855 401 байт), всего 102,8 МБ. Float-веса не
распаковываются. SHA-256 архива вычислен по полной HTTPS-загрузке и закреплён
в манифесте: `c46116994e539aa165266d96b325252728429c12535eb9d8b6a2b10f129e66b1`.
Лицензия весов [MIT](https://github.com/openai/whisper/blob/main/LICENSE).
Все загрузки проверяют размер и SHA-256 перед атомарной установкой.

Веса обеих ASR-моделей и tiny одновременно находятся в памяти воркера.
Перед диаризацией они освобождаются. Авто требует больше RAM, чем одна модель;
аудио ASR по-прежнему читается потоком. Очень короткие фразы, шум и смена языка
без паузы внутри одного VAD-чанка могут определяться неверно. Это выбор языка
чанка, а не пословное переключение моделей.

Словарь и его алиасы передаются обеим ASR-моделям как hotwords, включая
`modified_beam_search`. После распознавания общий post-fix восстанавливает
латинское написание по явным алиасам, например `Kubernetes = кубернетес`.
Hotwords увеличивают CPU-затраты. Сами слова словаря не влияют на Language ID.

`transcript.json` остаётся версии 1: `segments[].lang` необязателен,
`#[serde(default)]`, при неизвестном языке поле отсутствует. Старые транскрипты
читаются без миграции; редактирование и назначение спикеров сохраняют язык.
GigaAM в одиночном режиме помечает сегменты `ru` по выбранной модели.

## Потоки и измерение скорости

`asr_threads = 0` означает `min(physical cores, 8)`, минимум один поток.
Можно явно выбрать 1-8. Значение применяется к recognizer, Language ID, VAD,
segmentation и voice embedding. Настройка передаётся в `load_model.num_threads`;
старые клиенты без этого поля получают автоматический выбор.

```sh
notetaker-asr bench input.wav --model auto --provider cpu --threads 0 --runs 3
```

RTF = время прохода / длительность WAV. Значение меньше 1 означает быстрее
реального времени. `load_s` выводится отдельно и не входит в RTF; проход
включает чтение/ресемплинг WAV, VAD, Language ID и декодирование, без диаризации
и hotwords. `--runs` повторяет проходы в одном процессе, сохраняя модели.

### Сравнение маршрутов на CPU

Локальный замер 2026-10-27: Linux x64, QEMU Virtual CPU 2.5+, четыре vCPU
без SMT, два потока на модель. VM общая с другими сборками. Медиана трёх
проходов после одной загрузки моделей, без hotwords:

| WAV | Аудио, с | Whisper + выбранная ASR, с | Parakeet-first, с |
| --- | ---: | ---: | ---: |
| `example.wav`, русский | 11,290 | 5,294 | 7,747 |
| `en.wav`, английский | 3,845 | 1,771 | 1,294 |
| ru + пауза + en + пауза | 17,135 | 8,001 | 13,116 |

Это суммы измеренных нативных вызовов на одинаковых VAD-чанках, без WAV I/O,
VAD и загрузки весов. Parakeet-first сначала декодирует чанк, считает долю
кириллических букв, затем повторяет русские чанки через GigaAM. Если запускать
обе ASR всегда, стоимость на этих трёх примерах составляет 7,75 / 2,46 /
14,56 с соответственно (медианы сумм двух проходов).

Оба маршрута выбрали язык верно на этих fixtures. Whisper дал `ru`, `ru`, `en`
на смешанном WAV. GigaAM восстановил «лукоморья дуб», тогда как Parakeet дал
«лукомория туб»; английский JFK корректно распознал Parakeet. Это smoke-проверка,
не WER-оценка реальных встреч. Выбран Whisper: он экономит повторный большой
ASR-проход на русской речи и определяет язык по звуку. Цена на английском -
дополнительный Language ID; для заведомо английской встречи можно выбрать
Parakeet напрямую. Модель Language ID весит 102,8 МБ дополнительно.

Воспроизведение исследования:

```sh
cargo test --release -p notetaker-asr-worker -p notetaker-pipeline -p notetaker-cli \
  routing_costs -- --ignored --nocapture
```

Пакеты указаны вместе, чтобы сохранить общий набор Cargo features и избежать
повторных сборок зависимостей. Строки `ROUTING` содержат результаты каждого
прохода. Значения заметно меняются с нагрузкой VM; порогов времени в тестах нет.

### Команда bench: полный ASR-проход

Тот же день и VM, `--provider cpu --runs 3`, без hotwords. Четыре потока
соответствуют `--threads 0`; два заданы явно. Медианы трёх проходов:

| Модель | WAV | Потоки | Проход, с | RTF |
| --- | --- | ---: | ---: | ---: |
| GigaAM | ru | 4 | 4,134 | 0,3661 |
| Parakeet | en | 4 | 2,809 | 0,7306 |
| Авто | ru | 4 | 5,997 | 0,5311 |
| Авто | en | 4 | 2,417 | 0,6285 |
| Авто | ru+en | 4 | 9,881 | 0,5767 |
| Авто | ru+en | 2 | 5,887 | 0,3436 |

Это отдельные процессы на общей VM с меняющейся нагрузкой. Для сравнения
маршрутов используются вызовы на одинаковых чанках из исследования выше;
здесь приведены наблюдаемые полные RTF с VAD и чтением WAV. Замеры нужно
повторить на целевом ПК, особенно при выборе числа потоков.

Загрузка весов отдельно заняла 4,82 с для GigaAM, 12,72 с для Parakeet и
13,64-21,55 с для Авто. Максимальный RSS по `/usr/bin/time`: 0,31 / 0,82 /
1,26-1,32 GiB соответственно. Это память всего Linux-воркера, не размер
установщика. Смена языка внутри уже загруженного Авто не перезагружает модели.

## Windows GPU

В 0.10.0 поставляется только CPU-воркер со статическими sherpa-onnx/ORT и MT CRT.
**GPU (DirectML): недоступно в этой сборке.** Пункт GPU в UI отключён. Авто
использует CPU, отдельной
загрузки GPU-addon нет. Явный GPU-режим возвращает понятную ошибку, не выдавая
CPU-работу за GPU-ускорение.

Подготовлена общая для app/pipeline схема выбора отдельного
`notetaker-asr-gpu.exe` рядом с CPU-воркером либо по `NOTETAKER_ASR_GPU_BIN`
(только Windows). Авто пробует его и при ошибке запуска/загрузки модели
переходит на CPU с нейтральным уведомлением. При отсутствии addon уведомления
нет. «Только CPU» никогда не запускает GPU-воркер. Ответ загрузки должен
подтвердить `provider: directml`; ответ `cpu` считается неудачей GPU-загрузки.
Это заготовка интеграции для будущего проверенного addon, не готовая GPU-сборка.

Что проверено для sherpa-onnx **v2.0.0**:

- В [assets релиза](https://github.com/k2-fsa/sherpa-onnx/releases/tag/v2.0.0)
  нет DirectML-сборок. CPU static-MT-Release-lib: 122 697 732 байта,
  static-MD-Release-lib: 95 988 855; shared-MT/MD-Release-lib: 7 878 613 /
  7 270 549 байт. Это размеры сжатых SDK-архивов, не итогового приложения.
- [DirectML CMake](https://github.com/k2-fsa/sherpa-onnx/blob/v2.0.0/cmake/onnxruntime-win-x64-directml.cmake)
  требует `BUILD_SHARED_LIBS=ON`, ONNX Runtime DirectML 1.14.1 и DirectML 1.15.0.
  Нужны отдельные `onnxruntime.dll`, `DirectML.dll` и shared sherpa DLL.
  Совместимость этого старого ORT с текущими экспортами моделей не проверена.
  CRT будущего addon тоже нужно закрепить отдельно: MT либо MD с его runtime.
- Windows CUDA 12/13 + cuDNN 9 + ORT 1.28.2 есть, архивы 597 164 474 /
  480 352 316 байт. Они требуют соответствующего NVIDIA runtime и не решают
  задачу Intel/AMD. Cargo feature `cuda` остаётся экспериментальной и не включён
  в штатной CI/release-сборке.
- [DirectML EP](https://onnxruntime.ai/docs/execution-providers/DirectML-ExecutionProvider.html)
  требует DirectX 12 и последовательного исполнения с отключённым memory
  pattern. [sherpa session.cc](https://github.com/k2-fsa/sherpa-onnx/blob/v2.0.0/sherpa-onnx/csrc/session.cc)
  умеет откатываться на CPU при ошибке провайдера. Будущему addon нужна реальная
  проверка EP и графов int8 на Intel/AMD/NVIDIA, а не только успешный load.

GPU-addon не собирается и не публикуется до этих проверок. Будущий дистрибутив
следует держать в отдельном `notetaker-gpu-addon-<ver>-windows-x64.zip`, проверять
SHA-256 до установки в data dir и запускать без зависимости основного пакета
от его DLL. Нельзя просто подложить другой `onnxruntime.dll` к CPU-бинарнику.

CI и Release запускают `check-asr-providers.ps1`: CPU доступен, DirectML явно
отклоняется. `package-windows.ps1` сохраняет audit динамического CRT и также
отклоняет ML DLL imports и случайные GPU DLL в основном payload. Native libs
продолжают кэшироваться и загружаться существующим `fetch-sherpa-libs.sh`.

## Проверки с реальными моделями

```sh
export SHERPA_ONNX_LIB_DIR="$PWD/target/sherpa-libs/sherpa-onnx-v2.0.0-linux-x64-static-lib/lib"
export NOTETAKER_MODELS_DIR=/path/to/models
cargo build --release -p notetaker-asr-worker -p notetaker-cli -j 2
cargo test --release -p notetaker-asr-worker -p notetaker-pipeline -p notetaker-cli \
  -- --ignored --nocapture --test-threads=1
```

Auto-тест объединяет GigaAM `example.wav` (11,29 с, русский) и Parakeet `en.wav`
(3,845 с, английский) с секундными паузами. Проверяются оба языка, текст,
таймстампы и смещение PCM. Pipeline дополнительно проверяет import, алиасы
словаря, запись `lang` и сохранение после редактирования. У тестов нет порогов
скорости, зависящих от нагрузки CI.

Локально выполнено: `cargo fmt --all --check`, Clippy всех targets с
`-D warnings`, `cargo test --workspace` (260 passed, 8 ignored), затем все
восемь ignored-проверок (6 ASR, 2 pipeline, 0 failed). ASR/протокол также прошли
`cargo check --target x86_64-pc-windows-msvc` на Linux. Этот check не выполняет
Windows linking или запуск. Нативные MT imports, PowerShell packaging и
реальные Windows-модели должны проверяться Windows CI и вручную; в этой
сессии push/запуск CI не выполнялся.
