# Расширение заметок через LLM

## Подключение в приложении

Открой **Настройки → Подключение AI**, выбери карточку и нажми
**Использовать по умолчанию**. Приложение проверит подключение и сохранит выбор.
При выборе облачного AI режим новых встреч переключается с Local на Hybrid,
о чём появляется сообщение. Режим уже созданных встреч не меняется.
**Проверить** отправляет короткий запрос `ok`, показывает задержку или ошибку;
проверка может расходовать лимит подписки или шлюза. Таймаут проверки 30 секунд.

- **Claude (подписка)**: установи [Claude Code](https://code.claude.com/docs)
  (`npm i -g @anthropic-ai/claude-code`). Кнопка **Войти** открывает консоль Claude;
  выполни `/login`. Можно выбрать sonnet, opus, haiku или оставить модель CLI.
  notetaker запускает установленный неизменённый `claude -p --output-format json`,
  передаёт промпт через stdin и читает `result`. `--bare` не используется, поскольку
  он отключает вход через подписку. Приложение не реализует Claude.ai OAuth,
  не читает и не сохраняет токены Claude. Условия и доступность подписки определяет CLI.
- **ChatGPT (подписка)**: установи [Codex CLI](https://developers.openai.com/codex/cli)
  (`npm i -g @openai/codex`). **Войти** запускает `codex login` в отдельной консоли,
  CLI открывает браузер. Проверка сначала выполняет `codex login status`, затем
  короткий запрос. Генерация использует `codex exec --skip-git-repo-check -s read-only
  -o <file> -` в отдельном временном каталоге. Промпт приходит через stdin,
  конспект читается только из итогового файла; журналы CLI игнорируются.
  `~/.codex/auth.json` приложение не читает. Входом и моделью управляет сам CLI.
- **Flant LLM Gateway**: введи ключ. **Загрузить список моделей** обращается к
  `GET https://llm-api.flant.ru/v1/models` с Bearer-авторизацией; выбор по умолчанию
  делает то же самое автоматически. Выбирается `claude-sonnet-4-6`, если она
  доступна, иначе первая модель из списка. Ключ: **4o.flant.ru → Settings →
  Account → API Keys**. Шлюз доступен из VPN Фланта.
- **Свой шлюз**: укажи корень API, ключ, модель и тип OpenAI-совместимый / Anthropic.
  Список моделей загружается через `/models`; модель также можно вписать вручную.

На Windows ключ сохраняется в **Credential Manager** только после успешного
выбора по умолчанию, под именем `notetaker/llm/<provider-id>`. Поле скрывает ввод;
пустое поле оставляет сохранённый ключ. Ключи не попадают в TOML и диагностику.
На других ОС используется прежний `api_key_env`: добавь имя переменной в
**Расширенные**, сохрани настройки и задай переменную перед запуском приложения.
Полный редактор провайдеров и defaults находится в **Расширенные**.
Карточки проверяют состояние по нажатию; надпись «Подключено» относится к последней
успешной проверке, а не к постоянному мониторингу доступности.

CLI ищутся в PATH; на Windows также в `%USERPROFILE%\.local\bin` и
`%APPDATA%\npm` (включая `.exe` и `.cmd`). Фоновые вызовы не открывают консоль.
На Linux кнопка входа использует `x-terminal-emulator`; при его отсутствии выполни
вход вручную в терминале. Временные файлы промпта и ответа удаляются после вызова.
CLI имеют лимит 10 минут на каждый map/reduce-запрос и кнопку **Отменить**.
Claude вызывается с отключёнными инструментами (`--tools ""`), Codex получает
read-only sandbox и инструкцию не использовать инструменты. Настройки и доступные
инструменты CLI остаются под управлением установленного пользователем CLI.

## Автоматический конспект и правки

**Делать конспект автоматически** включено по умолчанию. После успешного
чистового прохода приложение ждёт сохранения заметок и запускает генерацию,
если настроен провайдер, разрешённый режимом встречи. Используется шаблон встречи
(по умолчанию `general`). Полоса прогресса показывает генерацию; ошибка выводится
в уведомлении, прежний конспект сохраняется. Кнопка ручного запуска остаётся доступной.

В `meta.yaml` добавлено необязательное поле `summary` с хешами входных данных
(заметки, транскрипт, выбранный шаблон) и сгенерированного Markdown. Оно читается
через `serde(default)`; старые встречи продолжают открываться без миграции,
sidecar не нужен. Хеши сравнивают содержание, а не время изменения файлов.
После изменения заметок, сегментов или выбора шаблона появляется чип
**Конспект устарел** и кнопка **Обновить**. Если пользователь изменил сам конспект,
автоматическая генерация его не заменит: нужен явный клик **Пересоздать**.
Старый непустой конспект без stamp также считается пользовательским.
Если входные данные меняются во время генерации, результат сразу помечается устаревшим.
Защита ревизий сохраняет внешний вариант enhanced.md при конфликте во время запроса.

## CLI

```sh
notetaker enhance /path/to/library/2026-10-26_1530_planning
notetaker enhance /path/to/meeting --template client-call --provider cloud
```

Команда читает `meta.yaml`, `notes.md` и `transcript.json`, печатает Markdown
и атомарно заменяет `enhanced.md`. При ошибке прежний файл сохраняется.
Шаблон выбирается из `--template`, затем `meta.template`, затем `general`.
Каталог библиотеки - родитель папки встречи. ASR и аудио не используются.

## Конфигурация

Файл `ProjectDirs::from("", "", "notetaker").config_dir()/config.toml`:

- Linux: `$XDG_CONFIG_HOME/notetaker/config.toml` или `~/.config/notetaker/config.toml`;
- Windows: `%APPDATA%\notetaker\config\config.toml`;
- macOS: `~/Library/Application Support/notetaker/config.toml`.

Приложение создаёт файл при сохранении настроек; его можно редактировать вручную.
Ключи в него не записываются. `api_key_env` содержит
**имя** переменной окружения с ключом. Для локального сервера без авторизации
поле можно опустить. Указанная переменная должна существовать и быть непустой.

```toml
[defaults]
local = "ollama"
hybrid = "cloud"

[[providers]]
id = "ollama"
kind = "openai"
base_url = "http://localhost:11434/v1"
model = "qwen3:8b"
context_tokens = 8192

[[providers]]
id = "cloud"
kind = "openai"
base_url = "https://api.openai.com/v1"
model = "<OPENAI_MODEL>"
api_key_env = "OPENAI_API_KEY"
context_tokens = 32768

[[providers]]
id = "claude"
kind = "anthropic"
base_url = "https://api.anthropic.com/v1"
model = "<ANTHROPIC_MODEL>"
api_key_env = "ANTHROPIC_API_KEY"
context_tokens = 32768

[[providers]]
id = "claude-subscription"
kind = "claude-cli"
model = "sonnet"
context_tokens = 150000

[[providers]]
id = "codex-subscription"
kind = "codex-cli"
context_tokens = 150000

[[providers]]
id = "flant"
kind = "openai"
base_url = "https://llm-api.flant.ru/v1"
model = "claude-sonnet-4-6"
key_source = "credential"
context_tokens = 32768
```

`key_source = "env"` используется по умолчанию и сохраняет совместимость с
`api_key_env`. `key_source = "credential"` читает ключ из Windows Credential Manager
по id провайдера. CLI-провайдеры не используют эти ключи, их контекст по умолчанию
150000 токенов. `base_url` у CLI не нужен, пустой `model` оставляет выбор CLI.

Подставь доступные модели и их фактический размер контекста. Для Ollama также
настрой соответствующий контекст на стороне сервера: `context_tokens` ограничивает
клиентские запросы, но не меняет настройки модели. Обе записи в `[defaults]`
обязательны; они могут ссылаться на один локальный провайдер.
`--provider ID` переопределяет выбор для одной команды, сохраняя проверку режима.

`base_url` - корень API, **без** `/chat/completions` или `/messages`:

- OpenAI: `https://api.openai.com/v1`;
- OpenRouter: `https://openrouter.ai/api/v1`;
- Ollama: `http://localhost:11434/v1`;
- llama-server / vLLM: например `http://127.0.0.1:8080/v1`;
- Anthropic: `https://api.anthropic.com/v1`.

OpenAI-совместимый провайдер отправляет Chat Completions с `stream=true`,
читает SSE и принимает обычный JSON, если сервер игнорирует стриминг.
Anthropic использует Messages API, `anthropic-version: 2023-06-01` и `x-api-key`;
ответ целиком передаётся колбэку одним фрагментом. HTTP синхронный: в UI вызывай
его вне основного потока. Автоматических повторов запросов нет.
Тела HTTP-ошибок и значения ключей не включаются в диагностику.

## Local-only

CLI-провайдеры считаются облачными и запрещены для Local с русским сообщением.
Для HTTP-провайдеров при `mode: local` URL проверяется **до** чтения ключа и создания клиента.
Разрешены только `localhost` и loopback IP (`127.0.0.1`, `::1`). Удалённый
провайдер отклоняется, в том числе при явном `--provider`.
У loopback-клиента отключены HTTP-прокси, `localhost` привязан к loopback IP.
Редиректы отключены у всех провайдеров. URL с credentials, query или fragment
не принимаются. Для `hybrid` удалённые провайдеры разрешены.

## Шаблоны

Встроены `general`, `one-on-one`, `client-call`, `standup`. Инструкции на
английском, результат - на языке транскрипта (по умолчанию русском). Все встроенные
шаблоны используют `- [ ] Задача - Ответственный - срок` для действий; отсутствующие
владелец и срок помечаются «не указан», а не выдумываются. Пользовательский шаблон
`<library>/.templates/<name>.md` имеет приоритет над встроенным с тем же именем:

```markdown
---
name: Release review
description: Decisions and follow-ups for a release
---
Preserve the user's agenda. Expand it with evidence from the meeting.
Use sections: Release scope, Decisions, Risks, Action items.
Include owners and deadlines only when stated.
Write the notes in the language of the meeting.
```

Применение: `--template release-review`, если файл называется
`release-review.md`. `name` и `description` - отображаемые метаданные,
тело - инструкция. Имя файла: латинские буквы, цифры, `-`, `_`.

## Промпт и длинные встречи

Заметки пользователя - каркас и приоритет: каждый пункт нужно сохранить,
развернуть по транскрипту, исправить опечатки и сокращения. Промпт запрещает
выдумывать факты, решения, владельцев и сроки; отсутствие пункта в транскрипте
не является поводом его удалить. Добавляются заголовок и дата встречи,
транскрипт с `[mm:ss]` и speaker ID (`me` / `them` в v1), инструкция шаблона.
Входные данные отделены от системных инструкций.

Оценка: около 4 Unicode-символов на токен с запасом (используем 3), плюс
64 токена на служебную обвязку. На ответ резервируется четверть контекста,
не более 2048 токенов. Токенизация приблизительная, особенно для не-латиницы.
Если провайдер отклоняет контекст, уменьши `context_tokens`.

Если транскрипт не помещается, он делится по строкам и границам Unicode;
для длинного сегмента метка времени и спикер повторяются. Каждый кусок
сжимается с исходными заметками, затем конспекты используются для итогового
свода по шаблону. Если конспекты тоже велики, добавляются уровни reduce.
Заметки, метаданные и шаблон передаются на каждом шаге. Финальные фрагменты
вызывают колбэк; промежуточные конспекты остаются внутри крейта.

Не более 8 проходов сжатия; отсутствие сокращения даёт ошибку. Если сами
заметки и шаблон не помещаются, команда просит увеличить контекст или
сократить их, не обрезая молча. Пустые ответы, обрыв SSE и достижение лимита
ответа считаются ошибкой. Map-reduce требует нескольких последовательных
запросов и может терять детали при сжатии.

## API и проверка

Крейт `notetaker-llm`: `Config::{load,from_path,parse,select}`,
`Template::{load,builtin}`, `create_provider(config, mode, cancellation)`,
`HttpProvider::new(config, mode)`, `HttpProvider::models()`,
трейт `Provider::{config,complete}` и `CompletionRequest` с ограничением ответа.
`enhance` возвращает Markdown; `enhance_meeting` дополнительно читает файлы
через core и атомарно пишет результат. Оба принимают `&mut dyn FnMut(&str)`.
При ошибке колбэк мог получить часть ответа: сохранять его нужно только
после успешного завершения.

Тесты используют локальный `TcpListener`, фиктивные ключи и провайдеры:
SSE/JSON, Anthropic, HTTP 4xx/5xx, local-only, редиректы, шаблоны,
контекст и map-reduce, поддельные CLI-скрипты (Unix), отмена и таймауты,
мок credential store, списки моделей, stamp и защита автоматической генерации. Живые API и модели для тестов не требуются.

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -j 2 -- -D warnings
cargo test --workspace -j 2
```
