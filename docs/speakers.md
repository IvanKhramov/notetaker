# Собеседники и голоса

В настройках включено «Разделять собеседников». Нажмите «Скачать модели
разделения собеседников» (около 47 МБ). Сеть используется только по этой
команде. Без моделей или при ошибке остаётся обычный транскрипт `them`.
«Участников: авто» повторно группирует чистые фрагменты речи и убирает
малые группы. Можно указать 1–32 голоса системной дорожки, без владельца микрофона.
Настройки применяются к новым записям и импорту.

Для существующей встречи с сохранённым `audio/system.opus` можно повторить
только диаризацию из CLI, без ASR и нового конспекта:

```sh
notetaker rediarize /path/to/meeting
notetaker rediarize /path/to/meeting --speakers 2
```

`--speakers` задаёт точное число голосов системной дорожки, без владельца
микрофона. При импорте это все голоса файла, включая владельца, если он там есть.
Параметр передаётся в sherpa как `num_clusters`; после segmentation активных
ID может оказаться меньше. Это не гарантирует выделение каждого реального человека.
Без флага число определяется автоматически. Нужны установленные
модели диаризации и `notetaker-asr` рядом с CLI (или `NOTETAKER_ASR_BIN`).
CLI сохраняет `transcript.before-diarization-<timestamp>.json`. Старые имена,
объединения, подсказки и связи голосов системной дорожки сбрасываются;
текст, правки, время и микрофон сохраняются. Локальные средние этой встречи
очищаются, библиотека подтверждённых голосов не меняется. Новые отпечатки
не сохраняются. Конспект и ранее экспортированные файлы нужно обновить отдельно.
Если аудио уже удалено по сроку хранения, повторный проход невозможен.

После остановки записи диаризация работает на системной дорожке; при импорте
на всей записи. Микрофон остаётся `me`. Кластеры `s1`, `s2`, ... нумеруются по
первому появлению. Реплика ASR получает спикера с наибольшей суммой временных
пересечений. Если одна реплика содержит несколько голосов, выбирается один;
диаризация не разделяет её текст на слова и не восстанавливает одновременную речь.

## Быстрые исправления и тайминги (0.7.0)

В транскрипте панель «Спикеры - кто сколько говорил» показывает цвет, имя,
время речи, долю, число реплик и ходов, самый длинный монолог. Доля считается
от суммы времени всех спикеров; одновременная речь засчитывается каждому.
Пересечения реплик одного спикера считаются один раз. Ход объединяет соседние
по времени реплики одного спикера с паузой до секунды; смена спикера начинает
новый ход. Тайминги основаны на границах ASR-реплик, не на выравнивании слов.
Нажмите цветную полосу таймлайна, чтобы перейти к реплике.

«Объединить с...» переносит все реплики в выбранного спикера. Его имя имеет
приоритет; без имени используется имя исходного. Последнее объединение можно
отменить, пока встреча открыта и не сделана другая правка спикеров. Последующие
исправления текста при отмене сохраняются. При включённой библиотеке голосов
объединяются локальные средние кластеров и образцы подтверждённой целевой записи;
отмена восстанавливает их, если библиотека не менялась после объединения.

Нажмите время реплики для выбора, Shift+клик выбирает диапазон, Ctrl+клик
добавляет или убирает реплику. В «Это говорил...» выберите существующего или
нового спикера либо участника связанного календарного события. Текст, каналы
и время выбранных реплик сохраняются. Переназначение не пересчитывает
акустические отпечатки. Исключение: приложение после синхронизации имён из Толка
пересчитывает их через `embed` по проверенным временам слов Толка, если включена
библиотека голосов и сохранено аудио.
Разделение одной реплики пока не поддержано.

Нажмите имя над репликой, выберите «Переименовать», введите имя и нажмите
«Назвать». Поле получает фокус сразу. «Открыть человека» в этом меню доступно
при устойчивой voice-связи. Действия в панели спикеров сохраняются.
Имя применяется ко всем репликам спикера этой встречи. Для связанного голоса
при включённой библиотеке доступно «Применить ко всем встречам с этим голосом».
Связь определяется устойчивым voice ID, а не совпадением имени. Неподтверждённые
догадки в старых встречах остаются подсказками. Исправление неверной подсказки
другим именем без массового переименования выбирает другую голосовую запись.
Встречи, записанные до появления voice ID, автоматически по имени не связываются.

Правки атомарно сохраняются с проверкой revision транскрипта, обновляют поиск
и делают конспект устаревшим; конспект автоматически не перезаписывается.
При массовом переименовании каждый файл сохраняется отдельно. При ошибке
часть встреч уже может быть обновлена; повторите команду после устранения ошибки.

Меню «Экспорт» обновляет в папке встречи постоянный файл `<slug>.transcript.<format>`: транскрипт Markdown
с именами и временем, SRT, VTT, CSV (`start,end,speaker,text`, время HH:MM:SS.mmm)
или JSON с таймингами, статистикой и репликами. CLI пишет результат в stdout:

```sh
notetaker export /path/to/meeting --format md
notetaker export /path/to/meeting --format srt > transcript.srt
```

Форматы: `md|srt|vtt|csv|json`. Read-only MCP-инструмент
`get_speaker_timeline(meeting)` принимает UUID или путь встречи внутри библиотеки
и соблюдает существующий фильтр Local. Экспорт не содержит голосовых отпечатков.

## Библиотека голосов

«Голоса: запоминать имена» выключено по умолчанию. Голосовые отпечатки являются
биометрическими данными. При включении после новой встречи сохраняются средние
нормированные embedding-и кластеров и микрофона. Для записи в библиотеку явно
назовите спикера либо нажмите «Это я» в меню его имени. Для `me` можно сначала
ввести собственное имя. Настройка «Как вас зовут» подставляет имя по умолчанию,
если собственного имени во встрече ещё нет; подтверждённое имя сохраняется. «Это я» доступно также для кластеров импорта.

На следующей встрече cosine >= 0.70 с отрывом >= 0.10 подставляет имя с отметкой
«по голосу», если включена автоматическая подстановка. От 0.65 с отрывом 0.08
остаётся подсказка «Имя?», которую нужно подтвердить. LLM получает сильные имена,
но не подсказки. При импорте автоматическое совпадение сохраняет обычный `sN`:
оно не становится микрофоном или подтверждением «Это я». Основание и ограничения
порогов приведены ниже; шум, язык и устройство меняют точность.
Среднее вычисляется из не более восьми чистых фрагментов по 1–15 секунд;
пересечения разных голосов не используются для enrollment.

В настройках «Голоса» можно удалить голосовую запись со всеми её образцами. Выключение
опции прекращает новое накопление и сопоставление, но не удаляет сохранённые
данные. Удаление голоса не меняет подтверждённые имена старых встреч.

После сверки с Толком автоматический enrollment использует стабильный ID
зарегистрированного пользователя, а не имя. При совпадении имени с другой
голосовой записью сохраняется только имя в транскрипте; уточните его для сохранения
голоса. Регистр и пробелы по краям не различают имена.
Особой обработки букв вроде ß нет. Старые дубликаты не
объединяются и не переименовываются. Гости автоматически не обучаются; явное ручное именование
остаётся доступно. Чистые интервалы строятся из слов Толка с исключением других
голосов на ±300 мс; нужны 6 секунд, до восьми фрагментов по 1,5–15 секунд.
Микрофон считается собственным голосом только у встреч из реестра записей этой
установки. Импорты, общие встречи коллег и старые записи в этот реестр не добавляются.
Владелец ключа обучается только с микрофона, без отдельной записи `ktalk-*`;
остальные участники используют системную дорожку. Неоднозначное имя владельца
прекращает автоматическое обучение. Совпадение имени гостя или другого спикера
с собственным именем не сохраняет голос. Собственная запись находится только по
`is_me`; «Это я» и микрофон зарегистрированной встречи не превращают обычную
запись в собственную, даже при совпадении имени.
Незавершённое обучение возобновляется с повторной проверкой Толка без срока давности,
только пока revision и источник Толка соответствуют применённой сверке.
Обучение начинается через две минуты после сверки и закрытия уведомления.
До этого отмена меняет только транскрипт; после начала обучения исправляйте
имена вручную и удаляйте неверные голоса в настройках.

## Хранение и приватность

Журналы отмены из неизданных сборок автоматически удаляются при запуске.

- `transcript.json` версии 1: необязательные `speaker_names`,
  `speaker_suggestions`, `self_speaker`, `speaker_voice_ids` (спикер -> voice ID);
  `voice_recognitions` (автоматическое имя, voice ID, сходство) и `voice_rejected`.
  В `speaker_names` находятся только подтверждённые имена; старые файлы читаются без миграции.
- `<local-state>/voices.json`: модель, имена, до восьми embedding-ов на
  запись, `updated_at`, флаг собственного голоса, необязательный устойчивый `id`,
  ключи UUID встречи и Tolk identity для защиты от повторного обучения.
- `<local-state>/speaker-embeddings/<meeting-uuid>.json`: модель и средние
  embedding-и кластеров для последующего явного именования.

С 0.13.0 `<local-state>` для биометрии всегда находится в каталоге данных
пользователя, вне библиотеки: `ProjectDirs.data_local_dir()/libraries/<hash>/`.
Общие реестры в `.notetaker` можно синхронизировать, голосовые отпечатки
остаются на компьютере и не передаются LLM. Подробности переноса старых файлов:
[общая библиотека](sharing.md). Биометрические файлы не создаются, пока опция выключена.
Имена в `transcript.json` входят в переносимую встречу и могут попасть в Hybrid
LLM вместе с текстом. Удаление имени в настройках удаляет его enrollment из
`voices.json`; локальные средние встреч остаются для нового явного enrollment.
Для полного удаления отпечатков удалите также `speaker-embeddings` вручную.

## Модели и реализация

Новых зависимостей нет. sherpa-onnx Rust **2.0.0** экспортирует
`OfflineSpeakerDiarization`, `SpeakerEmbeddingExtractor`, `SpeakerEmbeddingManager`.
Используются первые два; cosine и небольшой локальный JSON заменяют нативный
in-memory manager, чтобы GUI не линковался с ML. Sherpa сначала находит речь,
пересечения и исходные группы (complete linkage, distance 0.5). В автоматическом
режиме воркер заново получает embedding-и чистых ходов длиной от 1.5 секунды
с окнами до 10 секунд. Average linkage с cosine distance 0.5 определяет число
групп. Группы с менее чем min(max(6 секунд, 2% обучающей речи), 10% обучающей речи) переносятся к ближайшим
крупным центроидам; крупнейшая группа всегда сохраняется. Это не предел числа людей.
Для расчёта linkage берутся до 512 ходов детерминированной псевдослучайной выборкой по всей записи.
Ходы с хотя бы 0.5 секунды чистой речи назначаются по собственному embedding;
ещё более короткие и перекрытые используют среднее исходной группы.
Если чистой речи для сравнения нет, только для назначения используется исходное
аудио группы, включая overlap. Если вектора всё равно нет, исходный ID сохраняется.
Без обучающих ходов исходная разметка сохраняется целиком.
При явно заданном числе участников повторная кластеризация отключена:
sherpa сразу получает num_clusters. После segmentation число активных ID может оказаться меньше. Сравнение работает и без библиотеки голосов;
тогда векторы живут только в памяти воркера. Малые группы настоящих тихих людей
могут исчезнуть; точный счётчик не гарантирует правильное разделение голосов.
[Исследование и воспроизведение](diarization-evaluation.md).
Операции `diarize` и `embed` выполняются в `notetaker-asr`, JSON lines v1.
Перед диаризацией ASR-модель освобождается, embedding extractor создаётся после
освобождения diarizer. CPU, до восьми физических ядер по настройке ASR. Диаризация sherpa читает всю волну в RAM:
около 230 МБ на час PCM плюс модели и промежуточные данные. Отмена во время
нативного diarize ограничена тайм-аутом воркера; обычный ASR остаётся потоковым.

Манифест: `crates/asr-worker/src/models.rs`. Файлы не входят в дистрибутив;
загрузка по запросу с проверкой размера и SHA-256 до атомарной установки.

- [pyannote segmentation 3.0](https://github.com/k2-fsa/sherpa-onnx/releases/tag/speaker-segmentation-models):
  архив 6 958 444 байта, используется `model.int8.onnx` (~1.5 МБ).
  MIT, LICENSE включён в архив;
  [исходная модель](https://huggingface.co/pyannote/segmentation-3.0).
  SHA-256 архива:
  `24615ee884c897d9d2ba09bb4d30da6bb1b15e685065962db5b02e76e4996488`.
- [3D-Speaker ERes2Net base](https://github.com/k2-fsa/sherpa-onnx/releases/tag/speaker-recongition-models):
  `3dspeaker_speech_eres2net_base_sv_zh-cn_3dspeaker_16k.onnx`, 39 593 761 байт.
  [Apache-2.0](https://github.com/modelscope/3D-Speaker/blob/main/LICENSE).
  Это компактная пара из [примера sherpa](https://k2-fsa.github.io/sherpa/onnx/speaker-diarization/models.html),
  пригодная для извлечения голосов независимо от ASR-языка; русские созвоны
  требуют дополнительной оценки. SHA-256 файла:
  `1a331345f04805badbb495c775a6ddffcdd1a732567d5ec8b3d5749e3c7a5e4b`.

GitHub Release API не публикует digest этих assets. SHA-256 вычислены локально
из полных HTTPS-загрузок указанных release URLs; это фиксация байтов, а не
независимая подпись издателя.

## Проверка

```sh
export NOTETAKER_MODELS_DIR=/path/to/models
notetaker-asr download diarization
notetaker-asr download gigaam-v3
notetaker-asr download parakeet-v3
cargo test -p notetaker-asr-worker --test diarization -- --ignored --nocapture
```

Тест объединяет русского диктора GigaAM `example.wav` и английского диктора
Parakeet `en.wav`, ожидает два кластера без hint, проверяет embedding-и, hint=2
и восстановление после ошибочного запроса. Модели и WAV не входят в Git.
Локальная CPU-проверка 2026-10-27: **1 passed**, два автоматических кластера,
embedding-и по 512 чисел; весь тест с повторным hinted-проходом занял 73.38 с.

На Windows вручную: звонок с 2–3 участниками, авто/hint, отсутствие моделей,
переименование и повторное открытие, stale конспект, поиск по имени,
«Это я», новый импорт с собственным голосом, подтверждение «Имя?» и удаление.

## Автоматические имена по голосу (0.33.0)

При включённой библиотеке настройка «Подставлять имя по голосу без вопроса»
включена по умолчанию. Cosine от 0.70 с отрывом от следующего человека от 0.10
даёт имя и voice ID без вопроса. От 0.65 с отрывом от 0.08 остаётся «Имя?».
Сравнивается максимум по образцам человека. В одной встрече автоматически
выбирается только самый сильный спикер для каждого человека. Микрофон, имена
пользователя и Толка не перезаписываются.

Три источника имени: подтверждение пользователя, сверка с Толком
(`ktalk_sources`) и распознавание по голосу. Автоматическое имя хранится только
в необязательном `voice_recognitions`: имя, voice ID и сходство с точностью
до 0.001. В `speaker_names` его нет, автоматическая связь тоже не дублируется
в `speaker_voice_ids`. Оно помечено «по голосу», сходство видно
в tooltip. «Верно» или ручное именование подтверждает имя и разрешает enrolment
из кеша встречи. «Это не он» снимает имя и связь только этой встречи и блокирует
новую автоматическую подстановку для speaker ID; остаётся явный выбор голоса.
Человек и его образцы из библиотеки не удаляются. Отказ сохраняется при открытии
встречи; если старый импортированный кластер был `me`, он получает обычный ID.
Имя из настройки «Как вас зовут» не снимает отказ. Явный выбор человека или
переименование подтверждает имя; сверка с Толком может установить проверенную
личность. Для обучения собственного голоса нужны микрофон встречи этой установки
или явное «Это я», одного «Верно» у импортированного голоса недостаточно.

Автоматическое имя само себя не обучает. Нужны ручное подтверждение или
проверенная сверка с Толком. Толк заменяет неподтверждённое автоматическое имя.
Счётчик «Толк поправил распознавание по голосу: N раз из M» хранится локально
и не увеличивается от повторной сверки тех же данных. Сравниваются стабильные
identity, включая сохранённые Tolk aliases голосовой записи. Иное написание
имени той же identity не является ошибкой. Локальная UUID-запись без известной
связи с Tolk identity не входит в N/M. Ошибка чтения или записи счётчика только
попадает в diagnostics; имена, pending enrolment и возможность отмены сохраняются.

Массовое переименование меняет написание и сохраняет источник каждого имени,
включая сходство автоматического имени. Оно не подтверждает другие встречи.
Версия транскрипта остаётся 1. Writer версии 0.32 не увидит автоматические имена
и может потерять их при сохранении; неподтверждённое имя не станет подтверждённым.
Приложение с включённой библиотекой при открытии повторяет распознавание по
локальному кешу, соблюдая сохранённые отказы. Пустые поля не переписывают старые
файлы при обычном чтении. Старый writer может потерять и флаги отказа.

Сильные автоматические имена входят в `named_text` и доступны LLM для конспекта.
Подсказки «Имя?» по-прежнему не передаются. Отпечатки не передаются никакому LLM.

### Доступ к именам и правки

`speaker_identity` возвращает имя, voice ID и источник; `speaker_name` и
`speaker_identities` используют тот же путь разрешения. Через него читают имена:

- транскрипт, меню, панель спикеров и preview Толка;
- `named_text` для summary/chat, поиска, задач из LLM и MCP `get_meeting`;
- timeline, экспорт и MCP timeline;
- people, `has_person`, страницы людей и участники серий.

Только подтверждённый `speaker_names` намеренно читают enrolment голосов,
защита имён при sync, выбор подтверждённой identity при merge, микрофонные
подсказки и проверка pending enrolment. Остальные прямые обращения относятся
к хранению/undo или тестам.

Запись имён и отказ:

- распознавание пишет только `voice_recognitions`, отказ оставляет подсказку;
- `default_self_name` проверяет отказ и существующее автоматическое имя;
- ручное именование, выбор голоса и merge подтверждают имя; merge без имени
  переносит отказ, reassign без имени не подтверждает голос и сбрасывает его кеш;
- undo восстанавливает прежние имена, источники и отказы;
- массовая правка написания не меняет источник и отказ;
- проверенный sync пишет подтверждённое имя Толка, не угадывает по голосу;
- повторная диаризация очищает системные имена, но сохраняет флаги отказа.

### Измерение и выбор порогов

24 настоящие записи Толка, 10 зарегистрированных людей, семь из них в 10-22
записях каждый. 222 embedding-а вычислены собственной операцией `embed`:
до восьми чистых фрагментов по 1.5-15 секунд на образец, по word timings Толка.
Имена и записи здесь не публикуются.

| --- | ---: | --- | --- |
| Один человек, разные записи | 3321 | 1 / 5 / 25 / 50 / 75 / 95% | 0.54 / 0.65 / 0.76 / 0.84 / 0.88 / 0.92 |
| Разные люди | 21102 | 1 / 50 / 95 / 99% | 0.06 / 0.28 / 0.49 / 0.58 |

| --- | ---: | ---: |
| 0.65 | 5.2% | 0.09% |

без проверки переносить на другие группы, устройства и шум.
