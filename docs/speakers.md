# Собеседники и голоса

В настройках включено «Разделять собеседников». Нажмите «Скачать модели
разделения собеседников» (около 47 МБ). Сеть используется только по этой
команде. Без моделей или при ошибке остаётся обычный транскрипт `them`.
«Участников: авто» выбирает число кластеров по порогу 0.5; можно указать 1–32.
Настройки применяются к новым записям и импорту.

После остановки записи диаризация работает на системной дорожке; при импорте
на всей записи. Микрофон остаётся `me`. Кластеры `s1`, `s2`, ... нумеруются по
первому появлению. Реплика ASR получает спикера с наибольшей суммой временных
пересечений. Если одна реплика содержит несколько голосов, выбирается один;
диаризация не разделяет её текст на слова и не восстанавливает одновременную речь.

## Быстрые исправления и тайминги (0.7.0)

В транскрипте панель «Спикеры - кто сколько говорил» показывает цвет, имя,
время речи, долю, число реплик и ходов, самый длинный монолог. Доля считается
от суммы времени всех спикеров; одновременная речь засчитывается каждому.
Пересечения реплик одного спикера считаются один раз. Ход объединяет соседние
по времени реплики одного спикера с паузой до секунды; смена спикера начинает
новый ход. Тайминги основаны на границах ASR-реплик, не на выравнивании слов.
Нажмите цветную полосу таймлайна, чтобы перейти к реплике.

«Объединить с...» переносит все реплики в выбранного спикера. Его имя имеет
приоритет; без имени используется имя исходного. Последнее объединение можно
отменить, пока встреча открыта и не сделана другая правка спикеров. Последующие
исправления текста при отмене сохраняются. При включённой библиотеке голосов
объединяются локальные средние кластеров и образцы подтверждённой целевой записи;
отмена восстанавливает их, если библиотека не менялась после объединения.

Нажмите время реплики для выбора, Shift+клик выбирает диапазон, Ctrl+клик
добавляет или убирает реплику. В «Это говорил...» выберите существующего или
нового спикера либо участника связанного календарного события. Текст, каналы
и время выбранных реплик сохраняются. Переназначение не пересчитывает
акустические отпечатки. Разделение одной реплики пока не поддержано.

Нажмите имя в панели или над репликой, введите имя и нажмите «Назвать».
Имя применяется ко всем репликам спикера этой встречи. Для связанного голоса
при включённой библиотеке доступно «Применить ко всем встречам с этим голосом».
Связь определяется устойчивым voice ID, а не совпадением имени. Неподтверждённые
догадки в старых встречах остаются подсказками. Исправление неверной подсказки
другим именем без массового переименования выбирает другую голосовую запись.
Встречи, записанные до появления voice ID, автоматически по имени не связываются.

Правки атомарно сохраняются с проверкой revision транскрипта, обновляют поиск
и делают конспект устаревшим; конспект автоматически не перезаписывается.
При массовом переименовании каждый файл сохраняется отдельно. При ошибке
часть встреч уже может быть обновлена; повторите команду после устранения ошибки.

Меню «Экспорт» обновляет в папке встречи постоянный файл `<slug>.transcript.<format>`: транскрипт Markdown
с именами и временем, SRT, VTT, CSV (`start,end,speaker,text`, время HH:MM:SS.mmm)
или JSON с таймингами, статистикой и репликами. CLI пишет результат в stdout:

```sh
notetaker export /path/to/meeting --format md
notetaker export /path/to/meeting --format srt > transcript.srt
```

Форматы: `md|srt|vtt|csv|json`. Read-only MCP-инструмент
`get_speaker_timeline(meeting)` принимает UUID или путь встречи внутри библиотеки
и соблюдает существующий фильтр Local. Экспорт не содержит голосовых отпечатков.

## Библиотека голосов

«Голоса: запоминать имена» выключено по умолчанию. Голосовые отпечатки являются
биометрическими данными. При включении после новой встречи сохраняются средние
нормированные embedding-и кластеров и микрофона. Для записи в библиотеку явно
назовите спикера либо нажмите «Это я» в меню его имени. Для `me` можно сначала
ввести собственное имя. Настройка «Как вас зовут» подставляет имя по умолчанию,
если собственного имени во встрече ещё нет; подтверждённое имя сохраняется. «Это я» доступно также для кластеров импорта.

На следующей встрече совпадение cosine >= 0.65 с отрывом >= 0.08 от следующего
имени показывается как «Имя?». Нажмите имя и подтвердите. LLM не получает
неподтверждённые догадки. В импортированной записи собственный голос при
cosine >= 0.85 получает id `me` и подтверждённое ранее имя. Пороги эвристические,
не калиброваны для идентификации личности; шум, язык и устройство меняют точность.
Среднее вычисляется из не более восьми чистых фрагментов по 1–15 секунд;
пересечения разных голосов не используются для enrollment.

В настройках «Голоса» можно удалить имя со всеми его образцами. Выключение
опции прекращает новое накопление и сопоставление, но не удаляет сохранённые
данные. Удаление голоса не меняет подтверждённые имена старых встреч.

## Хранение и приватность

- `transcript.json` версии 1: необязательные `speaker_names`,
  `speaker_suggestions`, `self_speaker`, `speaker_voice_ids` (спикер -> voice ID);
  старые файлы читаются без миграции.
- `<library>/.notetaker/voices.json`: модель, имена, до восьми embedding-ов на
  имя, `updated_at`, флаг собственного голоса, необязательный устойчивый `id`.
- `<library>/.notetaker/speaker-embeddings/<meeting-uuid>.json`: модель и средние
  embedding-и кластеров для последующего явного именования.

**Весь `.notetaker` является локальным каталогом: исключите его из синхронизации
и публикации библиотеки.** Приложение не синхронизирует его и не передаёт
embedding-и LLM. Биометрические файлы не создаются, пока опция выключена.
Имена в `transcript.json` входят в переносимую встречу и могут попасть в Hybrid
LLM вместе с текстом. Удаление имени в настройках удаляет его enrollment из
`voices.json`; локальные средние встреч остаются для нового явного enrollment.
Для полного удаления отпечатков удалите также `speaker-embeddings` вручную.

## Модели и реализация

Новых зависимостей нет. sherpa-onnx Rust **2.0.0** экспортирует
`OfflineSpeakerDiarization`, `SpeakerEmbeddingExtractor`, `SpeakerEmbeddingManager`.
Используются первые два; cosine и небольшой локальный JSON заменяют нативный
in-memory manager, чтобы GUI не линковался с ML. Самописная кластеризация не нужна.
Операции `diarize` и `embed` выполняются в `notetaker-asr`, JSON lines v1.
Перед диаризацией ASR-модель освобождается, embedding extractor создаётся после
освобождения diarizer. CPU, до восьми физических ядер по настройке ASR. Диаризация sherpa читает всю волну в RAM:
около 230 МБ на час PCM плюс модели и промежуточные данные. Отмена во время
нативного diarize ограничена тайм-аутом воркера; обычный ASR остаётся потоковым.

Манифест: `crates/asr-worker/src/models.rs`. Файлы не входят в дистрибутив;
загрузка по запросу с проверкой размера и SHA-256 до атомарной установки.

- [pyannote segmentation 3.0](https://github.com/k2-fsa/sherpa-onnx/releases/tag/speaker-segmentation-models):
  архив 6 958 444 байта, используется `model.int8.onnx` (~1.5 МБ).
  MIT, LICENSE включён в архив;
  [исходная модель](https://huggingface.co/pyannote/segmentation-3.0).
  SHA-256 архива:
  `24615ee884c897d9d2ba09bb4d30da6bb1b15e685065962db5b02e76e4996488`.
- [3D-Speaker ERes2Net base](https://github.com/k2-fsa/sherpa-onnx/releases/tag/speaker-recongition-models):
  `3dspeaker_speech_eres2net_base_sv_zh-cn_3dspeaker_16k.onnx`, 39 593 761 байт.
  [Apache-2.0](https://github.com/modelscope/3D-Speaker/blob/main/LICENSE).
  Это компактная пара из [примера sherpa](https://k2-fsa.github.io/sherpa/onnx/speaker-diarization/models.html),
  пригодная для извлечения голосов независимо от ASR-языка; русские созвоны
  требуют дополнительной оценки. SHA-256 файла:
  `1a331345f04805badbb495c775a6ddffcdd1a732567d5ec8b3d5749e3c7a5e4b`.

GitHub Release API не публикует digest этих assets. SHA-256 вычислены локально
из полных HTTPS-загрузок указанных release URLs; это фиксация байтов, а не
независимая подпись издателя.

## Проверка

```sh
export NOTETAKER_MODELS_DIR=/path/to/models
notetaker-asr download diarization
notetaker-asr download gigaam-v3
notetaker-asr download parakeet-v3
cargo test -p notetaker-asr-worker --test diarization -- --ignored --nocapture
```

Тест объединяет русского диктора GigaAM `example.wav` и английского диктора
Parakeet `en.wav`, ожидает два кластера без hint, проверяет embedding-и, hint=2
и восстановление после ошибочного запроса. Модели и WAV не входят в Git.
Локальная CPU-проверка 2026-10-27: **1 passed**, два автоматических кластера,
embedding-и по 512 чисел; весь тест с повторным hinted-проходом занял 73.38 с.

На Windows вручную: звонок с 2–3 участниками, авто/hint, отсутствие моделей,
переименование и повторное открытие, stale конспект, поиск по имени,
«Это я», новый импорт с собственным голосом, подтверждение «Имя?» и удаление.
