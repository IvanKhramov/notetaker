# Проверка лишних собеседников

## Причина

Cargo.lock фиксирует sherpa-onnx / sherpa-onnx-sys **2.0.0**. В этой версии
[кластеризация](https://github.com/k2-fsa/sherpa-onnx/blob/v2.0.0/sherpa-onnx/csrc/fast-clustering.cc#L38-L72)
использует complete linkage и расстояние `1 - cosine`. Больший порог уменьшает
число кластеров. При `num_clusters > 0` расстояние игнорируется.
Порог 0.5 соответствует
[официальному примеру с ERes2Net base](https://github.com/k2-fsa/sherpa-onnx/blob/v2.0.0/python-api-examples/offline-speaker-diarization.py#L51-L79),
но это не гарантия правильного числа голосов на созвоне.

Sherpa [исключает overlap и принимает уже 10 кадров речи](https://github.com/k2-fsa/sherpa-onnx/blob/v2.0.0/sherpa-onnx/csrc/offline-speaker-diarization-pyannote-impl.h#L393-L460)
внутри окна для embedding. Короткие и неодинаковые фрагменты одного голоса
могут оказаться далеко друг от друга. Complete linkage сохраняет их отдельно.
Это воспроизводится и без кодека: два голоса дали пять кластеров. Кодек,
короткие ходы и overlap дополнительно ухудшают входные данные.

В приложении один `diarize` получает всю системную WAV после финального ASR;
mic имеет отдельный ID `me`. Sherpa кластеризует окна глобально. Перенумерация
сохраняет число кластеров, библиотека голосов не создаёт новые ID.
Утечка микрофона в loopback может добавить голос владельца, но сама по себе
не объясняет десяток ID. Записи владельца для проверки здесь не было.

Отдельный дефект: построение средних пропускало целый ход при любом overlap.
В тесте короткое пересечение исключало несколько секунд пригодной речи.
Теперь используются чистые части, длинные фрагменты имеют приоритет.

## Первый этап (Linux CPU, 2026-11-02)

| --- | ---: | ---: | ---: | ---: |
| `2-clean-45s` | 2 | 5 | 4 | 0.641 / 0.819 |
| `2-call-45s` | 2 | 5 | 4 | 0.621 / 0.870 |
| `3-call-45s` | 3 | 7 | 4 | 0.622 / 0.767 |
| `4-call-45s` | 4 | 8 | 3 | 0.537 / 0.889 |
| `2-call-300s` | 2 | 19 | 11 | 0.282 / 0.568 |
| `3-call-300s` | 3 | 28 | 14 | 0.357 / 0.648 |
| `4-call-300s` | 4 | 30 | 13 | 0.245 / 0.616 |

Во всех семи случаях purity не снизилась. Это проверяется тестом, как и
отсутствие ухудшения one-to-one attribution более чем на 0.02.

**Проблема автоматического подсчёта полностью не устранена.** На длинных
degraded fixtures остаются лишние ID. На короткой записи с четырьмя голосами
тихий четвёртый голос уже смешан исходной моделью с другими, поэтому три
итоговых кластера не означают правильное распознавание всех участников.
Без уверенного акустического совпадения или известного числа голосов
принудительно уменьшать число до 2-4 небезопасно.

Реальный smoke-тест с русской GigaAM и английской Parakeet speech прошёл:
автоматически 2 голоса, два 512-мерных embedding, явный `speakers=2`,
восстановление после некорректного запроса. Ручная проверка CLI на сохранённом
Opus подтвердила точную резервную копию, сохранность текста, правок, времени,
mic, закладок, заметок и конспекта, очистку старых системных имён и voice ID.
Для известного созвона с двумя удалёнными людьми используйте
`notetaker rediarize <meeting> --speakers 2` при сохранённом system audio.

Проверки: `cargo fmt --all -- --check`,
`cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`,
оба ignored diarization-теста. Версия не менялась; UI и модели не менялись.

## Порог и ограничения

Проверены расстояния 0.5, 0.6 и 0.7. На коротких degraded fixtures:

| Голосов | 0.5: кластеры / purity | 0.6 | 0.7 |
| ---: | ---: | ---: | ---: |
| 2 | 5 / 0.937 | 4 / 0.937 | 3 / 0.937 |
| 3 | 7 / 0.830 | 7 / 0.830 | 5 / 0.793 |
| 4 | 8 / 0.889 | 7 / 0.893 | 5 / 0.806 |

Глобальное увеличение до 0.7 уменьшает число ID, но смешивает разные голоса.
На первом этапе оставлен 0.5, а исправление использовало средние кластеров с проверками
сходства, отрыва, длительности и одновременной речи. Ниже описан заменивший его второй этап.
Это эвристика, не идентификация личности. Слабый или неоднозначный остаток
лучше сохранить отдельным. На первом этапе явный `speakers` передавал число в sherpa. Ниже описан новый
fixed-count путь на чистых ходах, заменивший это поведение.

Число приглашённых не используется как предел: `EventLink` не определяет
владельца, фактически присоединившихся и людей у общего микрофона.

## Воспроизведение

Нужны ffmpeg с libopus, Python 3 без сторонних пакетов и модели из манифеста
приложения. [LibriSpeech test-clean](https://www.openslr.org/12/) занимает
около 330 MiB, лицензия [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/),
авторы корпуса Vassil Panayotov и соавторы. Использованы по восемь фрагментов
дикторов Peter Bobbe (1089), Nikolle Doolin (121), Dianne (1221), number6 (1320).

```sh
source ~/.cargo/env
export SHERPA_ONNX_LIB_DIR=$(bash scripts/fetch-sherpa-libs.sh | sed -n 's/^SHERPA_ONNX_LIB_DIR=//p' | tail -1)
export NOTETAKER_MODELS_DIR="$PWD/target/diarization-models"
cargo run -p notetaker-asr-worker -- download diarization
python3 scripts/diarization-fixtures.py
export NOTETAKER_DIARIZATION_EVAL_DIR="$PWD/target/diarization-eval"
cargo test -p notetaker-asr-worker --test diarization_eval -- --ignored --nocapture
```

Можно указать уже установленный каталог моделей. Скрипт создаёт детерминированные
45-секундные и 5-минутные записи с 2, 3 и 4 голосами, разным gain, ходами
0.35-0.8 секунды, более длинными фразами и короткими пересечениями. Call-вариант
проходит фильтры 200-3400 Hz, 8 kHz и Opus voip 12 kbit/s, затем возвращается
в mono 16 kHz. Один голос в four-speaker варианте говорит только короткими ходами.
Это нарезка английской книжной речи, не настоящие русские «угу» или «да».

Большие файлы, эталонная разметка, промежуточные кластеры и JSON-отчёты остаются
под игнорируемым `target/diarization-eval`. Тест кэширует сырой проход sherpa,
чтобы изменение cleanup не требовало повторять segmentation. При изменении
fixtures, моделей или версии sherpa используйте новый каталог `--dir` и env.
`NOTETAKER_EVAL_FILTER` выбирает имя случая; `NOTETAKER_EVAL_THRESHOLD=0.6`
и `NOTETAKER_EVAL_BASELINE_ONLY=1` воспроизводят проверку порога.

Purity сопоставляет каждый кластер наиболее подходящему голосу и замечает ложные
объединения. One-to-one attribution дополнительно штрафует лишние кластеры:
находит лучшее взаимно однозначное сопоставление ID и эталонных голосов.
Обе оценки считаются по пересечению распознанной и эталонной речи; это не DER,
ошибки детектора речи и тишина внутри книжных фрагментов отдельно не оцениваются.
Число акустических кластеров может отличаться от числа ID, которые получили
длинные текстовые сегменты ASR. Короткий тихий участник может быть уже смешан
исходной моделью, даже если итоговый счётчик выглядит правильно.


## Второй этап: повторная кластеризация

Выбран **average linkage на новых embedding-ах чистых ходов с минимальной
длительностью группы**. Глобальный порог sherpa не повышается. Модели, версия
приложения, UI и явный `--speakers N` не меняются.

Опорные реализации:

- [pyannote.audio 3.1.1, clustering.py](https://github.com/pyannote/pyannote-audio/blob/3.1.1/pyannote/audio/pipelines/clustering.py):
  агломеративная кластеризация, ограничение обучающих embedding-ов, перенос
  малых групп к центроидам крупных, назначение embedding-ов ближайшему центроиду.
  У нас минимум задан секундами, а не числом embedding-ов.
- [NeMo 24.12, конфигурация diarization](https://docs.nvidia.com/nemo-framework/user-guide/24.12/nemotoolkit/asr/speaker_diarization/configs.html)
  и [Park et al., NME-SC](https://arxiv.org/abs/2003.02405):
  несколько масштабов окон и оценка числа голосов через eigengap.
  Проверенный здесь простой normalized-Laplacian eigengap с AHC не является
  полной реализацией NeMo NME-SC или multi-scale spectral clustering.

### Как работает новый default

1. Sherpa по-прежнему выделяет ходы и overlap на всей записи. Его слитные ходы
   одного ID дают более длинные окна, чем исходные embedding-и sherpa.
2. Из каждого хода вычитается речь других ID. Для обучения нужны хотя бы
   1.5 секунды чистой речи, окна ограничены 10 секундами. Векторы нормируются.
3. Average linkage объединяет пары с минимальным средним cosine distance,
   пока расстояние не превысит 0.5. Это автоматическая оценка числа групп,
   без встроенного ограничения «в созвоне не более четырёх человек».
4. Выживают группы с min(max(6 секунд, 2% обучающей речи), 10% обучающей речи). Предел 10% защищает короткие записи,
   как small-sample rule pyannote. Крупнейшая сохраняется всегда. До 512 обучающих ходов выбираются детерминированной псевдослучайной выборкой
   по всей записи; матрица расстояний и кубическая работа linkage ограничены.
5. Ходы с >=0.5 секунды чистой речи назначаются ближайшим центроидам по своему
   вектору. Более короткие и перекрытые используют среднее исходного ID.
   При полном отсутствии чистой речи embedding исходного аудио допускается
   только для назначения, не для обучения. При невозможности получить вектор
   исходный ID сохраняется. Без обучающих ходов сохраняется вся исходная разметка.
6. ID перенумеровываются по первому появлению. Биометрические векторы для
   библиотеки, когда она включена, пересчитываются после назначения.

Простое назначение каждого короткого хода по его собственному вектору ухудшало
purity: на `2-call-45s` получалось 0.918 вместо 0.937, на `4-call-45s`
0.875 вместо 0.889. Поэтому короткая ненадёжная речь не создаёт новые группы,
а самые короткие ходы используют агрегированное сравнение.

### Длинная проверка

Дополнительно проверен `3-call-1200s`, 20 минут с тремя голосами.
Первый cleanup на нём не запускался, сравнение с исходным sherpa:

| Режим | Активные ID | Purity | One-to-one |
| --- | ---: | ---: | ---: |
| Sherpa, distance 0.5 | 76 | 0.855 | 0.136 |
| Новый default | 4 | 0.877 | 0.834 |

Все восемь проверенных fixtures укладываются в отклонение <=1 от эталона,
без снижения purity. Длинная запись использует те же восемь исходных фрагментов
на диктора с новой нарезкой и gain; это проверка длительности, не новых людей
или новых акустических условий. 20-минутные файлы с двумя и четырьмя голосами
скрипт тоже создаёт, но в этом прогоне они не оценивались. Ignored-прогон
длинного случая занял 1617 с на Linux CPU с двумя потоками, параллельно другим
проверкам. Это время конкретного запуска, не изолированный performance benchmark.

### Явный `--speakers N`

Обновление 2026-11-02: оба режима используют один исходный проход sherpa с
`num_clusters = -1`, затем одни и те же embedding-и чистых ходов. В fixed-режиме
average linkage объединяет группы до N, независимо от distance 0.5, без удаления
малых групп по длительности. Короткие и перекрытые ходы используют тот же путь
назначения, что и auto. Только после него ID перенумеровываются по появлению.
Если чистых обучающих ходов меньше N или вектора получить нельзя, число активных
ID может отличаться от заданного. Из отсутствующей речи новые голоса не создаются.

Число N взято из эталона только для запроса, не для обучения или назначения.
Новый прогон повторно извлекает embedding-и из WAV; кэшируется только исходная
разметка sherpa. Ячейка: активные ID / purity / one-to-one.

| Fixture | Automatic | Fixed N, sherpa до | Fixed N, average linkage |
| --- | ---: | ---: | ---: |
| `2-clean-45s` | 2 / 0.962 / 0.962 | 2 / 0.962 / 0.962 | 2 / 0.962 / 0.962 |
| `2-call-45s` | 2 / 0.937 / 0.937 | 2 / 0.937 / 0.937 | 2 / 0.937 / 0.937 |
| `3-call-45s` | 4 / 0.924 / 0.827 | 3 / 0.793 / 0.793 | 3 / 0.809 / 0.809 |
| `4-call-45s` | 3 / 0.889 / 0.889 | 3 / 0.742 / 0.742 | 4 / 0.889 / 0.777 |
| `2-call-300s` | 2 / 0.920 / 0.920 | 2 / 0.904 / 0.904 | 2 / 0.920 / 0.920 |
| `3-call-300s` | 4 / 0.868 / 0.847 | 3 / 0.588 / 0.588 | 3 / 0.878 / 0.878 |
| `4-call-300s` | 5 / 0.837 / 0.793 | 4 / 0.817 / 0.780 | 4 / 0.834 / 0.828 |

Все семь fixtures теперь дают ровно N активных ID, включая четырёхголосный
45-секундный случай. На трёхголосных пяти минутах purity выросла с 0.588 до 0.878,
one-to-one с 0.588 до 0.878. На каждом fixture purity не ниже старого fixed-пути.

**Условие «fixed не менее чистый, чем auto» пока не выполнено.** На `3-call-45s`
получается 0.809 против 0.924; на `4-call-300s` 0.834 против 0.837. Для первого
случая перенос обучающих ходов по принадлежности дереву вместо ближайшего
центроида тоже дал 0.809: потеря происходит уже при разрезе дерева на три группы.
Ограничение слияния пересекающихся ходов также не улучшило результат. Эти
проверки сделаны отдельно на экспортированных векторах, без изменения default.
Purity может расти от дробления одного голоса; знание числа людей само по себе
не делает acoustic embeddings лучше. Подгонка порогов под эталон не добавлялась.
Дальнейшая работа над представлением голоса нужна для выполнения этого условия.
Fixed на 20 минутах в новом прогоне не оценивался.

### Ограничения второго этапа

Порог и минимум выбраны на этих fixtures. Это проверка устранения воспроизведённого
дефекта, не независимый benchmark. Нужна запись исходного проблемного созвона.
Четвёртый диктор в четырёхголосных fixtures говорит только короткими ходами;
счётчик в допустимом диапазоне не доказывает, что он восстановлен отдельно.
Правило минимальной длительности может убрать настоящего тихого участника.
Overlap без чистой речи остаётся слабым материалом для назначения.
Повторное получение embedding-ов увеличивает CPU-время; linkage ограничен,
но чтение WAV и исходный sherpa-проход всё ещё зависят от длины файла.

### Воспроизведение второго этапа

Для обычной проверки достаточно команд выше. Дополнительно:

```sh
# Добавить 20-минутные fixtures с теми же дикторами и условиями.
python3 scripts/diarization-fixtures.py --long-seconds 1200

# Проверка выбранного default и экспорт векторов для сравнения методов.
NOTETAKER_EVAL_DUMP=1 cargo test -p notetaker-asr-worker --test diarization_eval -- --ignored --nocapture

# NumPy нужен только этому исследовательскому скрипту, не приложению.
OPENBLAS_NUM_THREADS=1 python3 scripts/diarization-clustering-eval.py

# Точное число голосов на семи исходных fixtures, тот же кэш segmentation.
NOTETAKER_EVAL_FILTER=45s,300s NOTETAKER_EVAL_FIXED=1 cargo test -p notetaker-asr-worker --test diarization_eval -- --ignored --nocapture

# Воспроизвести cleanup первого этапа.
NOTETAKER_EVAL_LEGACY=1 cargo test -p notetaker-asr-worker --test diarization_eval -- --ignored --nocapture
```

`NOTETAKER_EVAL_FILTER=3-call-1200s` выбирает один длинный случай; запятая
объединяет несколько подстрок фильтра.
Скрипт сравнения читает только имеющиеся `*-comparison.json`; перед новым запуском
на изменённых моделях или аудио нужен новый каталог. Он не использует эталонные
голоса при кластеризации или выборе числа, только при расчёте метрик.
Ignored-тест default требует отклонение счётчика <=1 и отсутствие снижения purity
относительно исходного sherpa; fixed-тест требует ровно заданное число активных ID на этих fixtures.
Это проверка счётчика, не доказательство выполнения условия purity относительно auto.
