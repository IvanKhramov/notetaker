# Общая библиотека через Яндекс Диск (0.13.0)

Библиотека состоит из обычных файлов. Сервер notetaker не нужен. Подходит
Яндекс Диск, OneDrive, Dropbox, Google Drive или другая синхронизируемая папка.

## Настройка для команды

1. Создайте папку библиотеки на Яндекс Диске и выдайте участникам доступ.
2. На каждом компьютере дождитесь загрузки файлов. Выберите постоянное
   локальное хранение, чтобы заметки были доступны без сети.
3. В настройках notetaker каждый участник выбирает свою локальную копию той
   же общей папки как библиотеку.
4. В «Папки / общая библиотека» включите «Общая (синхронизируется)».
   Для известных имён каталогов приложение предлагает этот режим, но не
   включает его без выбора пользователя.
5. Дождитесь завершения синхронизации перед редактированием чужой встречи.
   Желательно, чтобы у встречи был один редактор в каждый момент времени.

## Что хранится локально

Маркер общей библиотеки: `<library>/.notetaker/library.json`. В общем режиме
индекс и будущие кеши используют `Library::local_state_dir()`:
`ProjectDirs.data_local_dir()/libraries/<SHA-256 абсолютного пути>/`.
На Windows это `%LOCALAPPDATA%\notetaker\data\libraries\...`, на Linux
`~/.local/share/notetaker/libraries/...`. Путь на каждом компьютере свой.
Изменение пути библиотеки создаёт новый кеш; SQLite пересобирается из файлов.
Старый `.notetaker/index.sqlite` не копируется и больше не используется.
Если он остался после старой версии, исключите его из синхронизации.

`voices.json` и `speaker-embeddings` всегда хранятся в этом локальном каталоге,
даже у личной библиотеки. При открытии старой личной библиотеки биометрия
переносится из прежнего `.notetaker`; перед включением общего режима перенос
тоже выполняется. Уже общая библиотека не импортирует старые голоса другого
участника. Если вы уже синхронизировали старые biometric-файлы, уберите их из
облачной папки и её истории вручную после проверки локальной копии.

`people.json`, `folders.json` и `vocabulary.txt` остаются общими. Не исключайте
весь `.notetaker`: это скроет настройки папок и ручные правки людей. Ключи
трекеров и LLM, настройки приложения и модели остаются на компьютере.

## Приватность

Local запрещает отправку текста удалённому LLM. Но файлы Local-встречи внутри
общей библиотеки всё равно загружает клиент Яндекс Диска. Приложение показывает
предупреждение у такой встречи. Для конфиденциальных встреч используйте
отдельную личную библиотеку вне синхронизируемой папки. Аудио, вложения,
metadata, имена спикеров и готовые конспекты в общей папке видят её участники
и дисковый провайдер в пределах своих правил доступа.

Отправка задачи в трекер - отдельное явное действие, с предварительным
просмотром и дополнительным подтверждением для Local.

## Конфликты

Атомарные сохранения текста и общих реестров проверяют revision прочитанного
файла. Если он изменился, внешняя версия остаётся, локальная сохраняется в
`.conflict-*`. Облачная синхронизация всё равно может создать свою копию.

Для `notes.md` и `enhanced.md` распознаются имена `notes (1).md`,
`notes-PC.md`, `notes (PC conflicted copy).md` и `.conflict-*` (аналогично
для конспекта). Встреча показывает «Найдена копия от синхронизации».
«Сравнить» показывает обе версии. Можно оставить мою, взять копию или
дописать обе. Исходная копия архивируется с суффиксом `.resolved-<uuid>`;
она не удаляется. Если файл изменился после сравнения, откройте его заново.

## Ограничения

- Это eventual sync файлов, без совместного редактора, сервера блокировок
  и разрешения одновременных правок отдельных символов.
- Новые встречи и копии подхватываются раз в 30 секунд при фокусе окна,
  когда нет записи, генерации или несохранённых правок. «Обновить» обновляет
  список вручную. Закрытое приложение не следит за синхронизацией.
- Автоматическое сравнение есть для заметок и конспектов. Копии metadata,
  транскриптов и JSON-реестров нужно сопоставлять вручную, сохраняя обе версии.
- Не редактируйте общую библиотеку старыми версиями notetaker: они пишут
  SQLite и биометрию по прежним путям и не сохраняют новые поля metadata.
- При удалении встречи синхронизатор удалит её и у остальных участников.
  Используйте историю версий дискового сервиса и резервные копии.
- Повторная отправка задач между компьютерами имеет отдельные
  [ограничения](trackers.md#повторная-отправка-и-сбои).
